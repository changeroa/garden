# screenDeltaToWorld

-   **다음:** `[[04-API-및-활용/worldDeltaToScreen]]`

## 📝 핵심 정리
화면에서의 픽셀 이동량(delta)을 월드 공간의 단위 이동량으로 변환합니다.

## 💻 코드 예제 (완전 주석)

```typescript
/**
 * ==========================================
 * [기능명]: 스크린 델타 -> 월드 델타 변환
 * ==========================================
 * 
 * 📖 목적: 마우스 드래그 같이 화면 기준의 이동 거리를 월드 공간에서의 이동 거리로 변환합니다.
 * 🏗️ 구조: 변환 행렬에서 이동(translation) 성분을 제외하고, 크기(scale) 성분만을 사용하여 변환합니다.
 * 🎯 학습포인트: 위치(position) 변환과 거리(delta) 변환의 차이점을 이해합니다.
 */
public screenDeltaToWorld(deltaX: number, deltaY: number): Point {
  // 최신 행렬 정보를 사용하기 위해 업데이트합니다.
  this.updateMatrices();
  
  // 역행렬에서 스케일 값만 가져옵니다. 역행렬의 [0] 요소는 x축 스케일의 역수입니다.
  // 이동(pan)은 위치에만 영향을 주고 거리에 영향을 주지 않으므로, 이동 성분(e, f)은 사용하지 않습니다.
  const scale = this.inverseViewMatrix[0];
  
  // 스크린 델타에 스케일 역수를 곱하여 월드 델타를 계산합니다.
  // y축은 부호를 맞출 필요가 없습니다. 왜냐하면 거리는 방향성이 달라도 크기는 같기 때문입니다.
  // 하지만 일반적으로 y축 방향을 일치시키기 위해 부호를 맞추는 경우가 많습니다. 이 코드에서는 x,y 동일 스케일을 가정합니다.
  return { x: deltaX * scale, y: deltaY * scale };
}
```

## 🔍 상세 분석

### 로직 포인트
-   **왜 이동(Translate) 성분을 무시하는가?**: `(x, y)` 같은 절대 위치는 화면의 원점이 어디냐에 따라 달라지지만, `(dx, dy)` 같은 이동 거리는 원점과 상관없이 동일합니다. 따라서 변환 행렬의 이동에 해당하는 `e`, `f` (행렬의 6, 7번째 요소) 값은 계산에 사용되지 않습니다.
-   **왜 스케일(Scale)만 사용하는가?**: 화면에서 10px 움직인 것은, 2배 줌 상태에서는 월드에서 5단위 움직인 것이고, 0.5배 줌 상태에서는 20단위 움직인 것입니다. 이처럼 델타 변환은 순수하게 줌 레벨, 즉 스케일 값에만 의존합니다. `inverseViewMatrix[0]`는 `1 / scaleX` 이므로, `deltaX / scaleX`를 계산하는 것과 같습니다.

### 실무 포인트
-   지도나 캔버스를 마우스로 드래그하여 패닝(panning)하는 기능을 구현할 때 필수적입니다. 마우스 `mousemove` 이벤트에서 얻은 `movementX`, `movementY` 값을 이 함수에 넣어 월드 이동량을 계산하고, 그만큼 `viewport.center`를 업데이트합니다.
