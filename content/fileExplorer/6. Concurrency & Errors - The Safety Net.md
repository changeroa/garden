# 🥅 동시성과 에러 처리: 안전망 구축하기

잘 만든 앱과 쉽게 망가지는 앱의 차이는 '해피 패스(Happy Path)'가 아닌, 예외적인 상황을 얼마나 잘 처리하는지에 달려있습니다. 동시성 문제와 에러는 앱을 망가뜨리는 가장 흔한 두 가지 원인입니다.

### 1. 동시성(Concurrency) 문제: 요청들의 경주

**상황**: 사용자가 인터넷이 느린 환경에서 `src` 폴더를 클릭해서 열기 시작합니다. 로딩 스피너가 돕니다. 기다리다 지친 사용자는 `assets` 폴더를 바로 이어서 클릭합니다.

- **요청 A**: `src` 폴더의 내용을 가져오기 시작 (10초 소요 예상)
- **요청 B**: `assets` 폴더의 내용을 가져오기 시작 (1초 소요 예상)

**경주 조건 (Race Condition) 발생!**

1.  요청 A가 출발합니다.
2.  요청 B가 출발합니다.
3.  1초 뒤, 요청 B의 응답이 도착합니다. UI는 `assets` 폴더의 내용으로 올바르게 업데이트됩니다.
4.  9초 뒤, **잊혀졌던 요청 A의 응답이 도착합니다!**
5.  앱은 요청 A의 결과를 최신 응답으로 착각하고, UI를 `src` 폴더의 내용으로 **덮어써 버립니다.**
6.  사용자는 분명 `assets` 폴더를 클릭했는데, 화면에는 `src` 폴더 내용이 보이는 혼란스러운 상황에 빠집니다.

### 해결책: `AbortController` - 이전 요청 취소하기

이 경주를 막는 가장 좋은 방법은, 새로운 경주가 시작될 때 이전 경주자를 실격시키는 것입니다.

`AbortController`는 진행 중인 `fetch` 같은 비동기 작업을 취소할 수 있는 신호를 보냅니다.

**[[3. State Management - The Single Source of Truth|Thunk]]에서의 구현:**

1.  `expandNode(nodeId)`가 호출되면, 먼저 `inflightById[nodeId]`에 저장된 이전 `AbortController`가 있는지 확인합니다.
2.  있다면, `controller.abort()`를 호출하여 이전 요청을 즉시 취소시킵니다.
3.  새로운 `AbortController`를 생성하여 `inflightById[nodeId]`에 저장합니다.
4.  이 컨트롤러의 `signal`을 `FsProvider.list(path, { signal })`에 전달하여 API 호출과 연결합니다.

이제 요청 A는 응답이 도착하기 전에 취소(abort)되고, 요청 B의 결과만 안전하게 처리됩니다.

### 2. 에러(Error) 처리: 모두를 위한 경보 vs. 개별 경보

**나쁜 예: 전역 `isLoading`, `error` 상태**

```typescript
interface State {
  isLoading: boolean;
  error: string | null;
}
```

- **문제**: 폴더 하나를 여는 데 실패하면(`Permission Denied`), 앱 전체가 에러 상태에 빠집니다. 다른 폴더를 탐색하는 것조차 막힐 수 있습니다. 마치 건물 전체에 화재 경보가 울려서 아무것도 못하는 것과 같습니다.

### 해결책: 노드별(Per-Node) 상태 - 똑똑한 개별 경보

우리가 [[3. State Management - The Single Source of Truth|Slice 스키마]]에서 설계한 방식입니다.

```typescript
interface State {
  statusById: { [id: string]: 'idle' | 'loading' | 'ready' | 'error' };
  errorById: { [id: string]: string | null };
}
```

- **장점**:
    - 폴더 A를 여는 데 실패하면, `statusById[folderA_id]`만 `'error'`가 됩니다.
    - UI는 이 상태를 보고, 폴더 A 옆에만 "다시 시도" 버튼이나 에러 아이콘을 표시할 수 있습니다.
    - 사용자는 다른 폴더 B, C를 자유롭게 탐색할 수 있습니다.
    - 마치 문제가 생긴 방에서만 작은 연기 감지기가 울리는 것과 같습니다. 훨씬 더 정확하고 사용자 친화적입니다.

이러한 안전망을 촘촘하게 구축함으로써, 우리는 예측 불가능한 네트워크 환경과 파일 시스템의 변덕 속에서도 안정적으로 동작하는 견고한 애플리케이션을 만들 수 있습니다.
