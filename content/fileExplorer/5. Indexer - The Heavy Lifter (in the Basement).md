# 👷‍♂️ 인덱서: 지하실의 일꾼

`Indexer`는 "프로젝트 전체 파일 스캔"처럼 무겁고 오래 걸리는 작업을 처리하는 전문 일꾼입니다. 이 일꾼의 가장 큰 특징은, 다른 사람들이 일하는 **메인 홀(Main Thread)이 아닌, 아무도 없는 조용한 지하실(Web Worker)에서 일한다**는 점입니다.

### 왜 분리해야 하는가? (The 'Why')

자바스크립트는 기본적으로 '싱글 스레드'입니다. 즉, 한 번에 하나의 일만 처리할 수 있습니다.

만약 수천 개의 파일을 읽고, 내용을 분석하고, 연관 관계를 파악하는 작업을 메인 스레드에서 실행하면 어떻게 될까요?

- **UI 프리징(Freezing)**: 작업이 끝날 때까지 앱 전체가 멈춥니다. 사용자는 스크롤도, 클릭도 할 수 없는 '벽돌'이 된 화면을 보게 됩니다. 최악의 사용자 경험입니다.

`Web Worker`는 메인 스레드와 완전히 분리된 별도의 스레드를 생성하여, 이런 무거운 작업을 백그라운드에서 처리하도록 해줍니다.

### 비유: 도서관 사서와 지하실

- **메인 스레드**: 도서관의 메인 홀. 방문객(사용자)들이 책을 읽고(UI 상호작용) 돌아다닙니다. 이곳은 항상 쾌적하고 반응이 빨라야 합니다.
- **Web Worker**: 지하실. 새로 들어온 수만 권의 책을 분류하고, 색인을 만들고, 정리하는(인덱싱) 시끄럽고 먼지 나는 작업이 이루어지는 곳입니다.
- **사서(Indexer)**: 메인 홀의 사서가 "이 책들 좀 정리해줘"라고 지하실로 책(데이터)을 내려보내면, 지하실의 사서가 묵묵히 일하고 결과(인덱스)만 다시 올려보냅니다. 메인 홀의 방문객들은 지하실에서 무슨 일이 일어나는지 전혀 알지 못합니다.

### 메인 스레드와 Worker의 통신 계약

둘은 서로의 메모리에 직접 접근할 수 없습니다. 오직 `postMessage`라는 '편지'를 통해서만 대화할 수 있습니다.

```typescript
// Main Thread (e.g., a Thunk)
const worker = new Worker('./indexer.worker.ts');

// Worker에게 일 시키기
worker.postMessage({ 
  type: 'START_INDEXING',
  payload: { files: [...] } 
});

// Worker로부터 보고 받기
worker.onmessage = (event) => {
  const { type, payload } = event.data;
  if (type === 'PROGRESS') {
    dispatch(updateIndexingProgress(payload)); // UI에 진행률 표시
  } else if (type === 'DONE') {
    dispatch(indexingComplete(payload)); // 결과물을 상태에 저장
  }
};
```

```typescript
// indexer.worker.ts (Web Worker)

self.onmessage = (event) => {
  const { type, payload } = event.data;
  if (type === 'START_INDEXING') {
    const results = processFiles(payload.files, (progress) => {
      // 메인 스레드에 진행 상황 보고
      self.postMessage({ type: 'PROGRESS', payload: progress });
    });
    // 메인 스레드에 최종 결과 보고
    self.postMessage({ type: 'DONE', payload: results });
  }
};
```

### 현실적인 제약: IO vs. CPU

- **CPU-bound 작업**: 파일 내용 파싱, 토큰화, 유사도 계산 등 순수 계산 작업. **이것이 Worker가 해야 할 핵심 역할입니다.**
- **IO-bound 작업**: 파일 읽기/쓰기.
    - **문제**: `File System Access API`의 `FileSystemHandle` 객체는 보안상의 이유로 Worker에게 직접 전달될 수 없는 경우가 있습니다.
    - **해결책**:
        1.  **(IO in Main, CPU in Worker)**: 메인 스레드가 파일을 읽어서 `ArrayBuffer`나 텍스트로 변환한 뒤, 이 데이터만 Worker에게 넘겨서 계산을 시킵니다.
        2.  파일을 청크(조각)로 나누어 Worker에게 순차적으로 보내 처리 부담을 줄일 수도 있습니다.

이처럼 Indexer를 Worker로 분리하는 것은 단순히 코드를 옮기는 것이 아니라, 두 스레드 간의 명확한 통신 계약을 설계하고 제약사항을 이해하는 과정이 필요합니다.
