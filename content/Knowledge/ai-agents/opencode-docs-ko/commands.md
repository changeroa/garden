# 명령

반복 작업을 위한 사용자 정의 명령 만들기.

사용자 정의 명령을 사용하면 TUI에서 해당 명령을 실행할 때 실행하려는 프롬프트를 지정할 수 있습니다.

```
/my-command
```

사용자 정의 명령은 `/init`, `/undo`, `/redo`, `/share`, `/help`와 같은 내장 명령에 추가됩니다. [자세히 알아보기](/docs/tui#commands).

---

## 명령 파일 만들기

사용자 정의 명령을 정의하기 위해 `command/` 디렉토리에 마크다운 파일을 만듭니다.

`.opencode/command/test.md` 만들기:

```markdown
---
description: 커버리지와 함께 테스트 실행
agent: build
model: anthropic/claude-3-5-sonnet-20241022
---

커버리지 보고서와 함께 전체 테스트 스위트를 실행하고 실패를 표시합니다.
실패한 테스트에 집중하고 수정 사항을 제안합니다.
```

프론트매터는 명령 속성을 정의합니다. 콘텐츠는 템플릿이 됩니다.

`/` 다음에 명령 이름을 입력하여 명령을 사용합니다.

```
"/test"
```

## 설정

OpenCode [설정](/docs/config)의 `command` 옵션을 통해 또는 `command/` 디렉토리에 마크다운 파일을 만들어 사용자 정의 명령을 추가할 수 있습니다.

### JSON

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "command": {
    // 이것이 명령의 이름이 됩니다
    "test": {
      // 이것이 LLM에 전송될 프롬프트입니다
      "template": "커버리지 보고서와 함께 전체 테스트 스위트를 실행하고 실패를 표시합니다.\n실패한 테스트에 집중하고 수정 사항을 제안합니다.",
      // 이것이 TUI에서 설명으로 표시됩니다
      "description": "커버리지와 함께 테스트 실행",
      "agent": "build",
      "model": "anthropic/claude-3-5-sonnet-20241022"
    }
  }
}
```

이제 TUI에서 이 명령을 실행할 수 있습니다:

```
/test
```

### Markdown

마크다운 파일을 사용하여 명령을 정의할 수도 있습니다. 다음 위치에 배치합니다:

- 전역: `~/.config/opencode/command/`
- 프로젝트별: `.opencode/command/`

마크다운 파일 이름이 명령 이름이 됩니다. 예를 들어, `test.md`는 다음을 실행할 수 있게 합니다:

```
/test
```

## 프롬프트 설정

사용자 정의 명령에 대한 프롬프트는 여러 특수 플레이스홀더와 구문을 지원합니다.

### 인수

`$ARGUMENTS` 플레이스홀더를 사용하여 명령에 인수를 전달합니다.

```markdown
---
description: 새 컴포넌트 만들기
---

TypeScript 지원이 포함된 $ARGUMENTS라는 새 React 컴포넌트를 만듭니다.
적절한 타이핑과 기본 구조를 포함합니다.
```

인수와 함께 명령 실행:

```
/component Button
```

`$ARGUMENTS`는 `Button`으로 대체됩니다.

위치 매개변수를 사용하여 개별 인수에 액세스할 수도 있습니다:

- `$1` - 첫 번째 인수
- `$2` - 두 번째 인수
- `$3` - 세 번째 인수
- 등등...

### 셸 출력

*!`command`*를 사용하여 [bash 명령](/docs/tui#bash-commands) 출력을 프롬프트에 주입합니다.

예를 들어, 테스트 커버리지를 분석하는 사용자 정의 명령을 만들려면:

```markdown
---
description: 테스트 커버리지 분석
---

현재 테스트 결과입니다:
!`npm test`

이 결과를 기반으로 커버리지를 높이기 위한 개선 사항을 제안합니다.
```

### 파일 참조

`@` 다음에 파일 이름을 사용하여 명령에 파일을 포함합니다.

```markdown
---
description: 컴포넌트 검토
---

@src/components/Button.tsx의 컴포넌트를 검토합니다.
성능 문제를 확인하고 개선 사항을 제안합니다.
```

파일 내용이 프롬프트에 자동으로 포함됩니다.

## 옵션

### template

`template` 옵션은 명령이 실행될 때 LLM에 전송될 프롬프트를 정의합니다. **필수** 설정 옵션입니다.

### description

`description` 옵션을 사용하여 명령이 수행하는 작업에 대한 간략한 설명을 제공합니다. 명령을 입력할 때 TUI에서 설명으로 표시됩니다.

### agent

`agent` 설정을 사용하여 이 명령을 실행할 [에이전트](/docs/agents)를 선택적으로 지정합니다. 지정하지 않으면 현재 에이전트가 기본값입니다.

### subtask

`subtask` 불리언을 사용하여 명령이 [서브 에이전트](/docs/agents/#subagents) 호출을 트리거하도록 강제합니다. 명령이 기본 컨텍스트를 오염시키지 않도록 하려는 경우에 유용합니다.

### model

`model` 설정을 사용하여 이 명령의 기본 모델을 재정의합니다.

## 내장

opencode에는 `/init`, `/undo`, `/redo`, `/share`, `/help`와 같은 여러 내장 명령이 포함되어 있습니다. [자세히 알아보기](/docs/tui#commands).

> **Note**: 사용자 정의 명령은 내장 명령을 재정의할 수 있습니다.

같은 이름의 사용자 정의 명령을 정의하면 내장 명령이 재정의됩니다.
