## 1. 개요 및 전략적 이점 (Introduction)

> [!SUMMARY] 핵심 개념
> 
> 가상 메모리란 사용자 **논리 메모리(Logical Memory)**와 **물리 메모리(Physical Memory)**를 분리하는 기법이다. 이를 통해 프로세스는 물리 메모리 크기의 제약을 받지 않고 대용량 주소 공간을 가질 수 있다.

### 1.1. 주요 이점

- **물리 메모리 제약 탈피:** 프로그램 전체를 메모리에 적재할 필요가 없음. (필요한 부분만 로드)
- **동시성(Concurrency) 향상:** 각 프로세스가 차지하는 메모리가 줄어들어, 더 많은 프로세스를 동시에 실행([[MPD]] 증가) 가능. $\rightarrow$ CPU 이용률 및 처리량 증대.
- **I/O 효율성:** 프로그램 로딩/스왑 시 필요한 페이지만 전송하므로 I/O 작업 감소.
- **프로세스 생성 최적화:** `fork()` 시 부모-자식 간 주소 공간 공유 가능 ([[#3. Copy-on-Write (COW)|COW 참조]]).
    

### 1.2. 가상 주소 공간 구조
- **구성:** 코드(Code), 데이터(Data), 힙(Heap $\uparrow$), 스택(Stack $\downarrow$).
- **희소 주소 공간(Sparse Address Space):** 힙과 스택 사이의 거대한 빈 공간(Hole)은 실제 물리 메모리를 점유하지 않으며, 동적 라이브러리 매핑 등에 활용됨.

## 2. 요구 페이징 (Demand Paging)

### 2.1. 기본 원리
- **Lazy Swapper:** 페이지가 실제로 필요할 때까지 메모리에 적재하지 않음.
- **Valid-Invalid Bit:** 페이지 테이블 항목에 `v`(메모리 있음), `i`(메모리 없음) 표시.
    

### 2.2. 페이지 폴트(Page Fault) 처리 과정

프로세스가 메모리에 없는 페이지(`i`)에 접근하면 **Trap** 발생.

1. **참조 확인:** 유효한 주소인지 확인 (무효면 Abort).
2. **빈 프레임 확보:** 물리 메모리에서 [[Free Frame]] 탐색 (없으면 [[#4. 페이지 교체 전략 (Page Replacement)|페이지 교체]] 수행).
3. **Swap-in:** 디스크에서 해당 페이지 읽어오기.
4. **테이블 갱신:** Valid 비트 설정 (`v`).
5. **재시작:** 중단된 명령어 재실행.
    

### 2.3. 성능 (Performance)

- 핵심 지표: 유효 접근 시간 (EAT)
    
    $$EAT = (1 - p) \times \text{Memory Access} + p \times \text{Page Fault Overhead}$$
    
    ( $p$: 페이지 폴트 확률 )
    
- **시사점:** 페이지 폴트 처리 시간(디스크 I/O)이 매우 크기 때문에, $p$를 0에 가깝게 유지하는 것이 필수적임.

## 3. Copy-on-Write (COW)

> [!NOTE] 프로세스 생성 최적화
> 
> fork() 호출 시 부모의 메모리를 모두 복사하는 대신, 일단 **공유(Read-Only)**하고 수정이 발생할 때만 복사하는 기법.

1. **초기 공유:** 부모/자식 페이지 테이블이 같은 물리 프레임을 가리킴 (권한: 읽기 전용).
2. **쓰기 시도:** 프로세스가 쓰기(Write)를 시도하면 트랩 발생.
3. **복사:** OS가 해당 페이지만 새로운 프레임에 복사 후 쓰기 권한 부여.
4. **[[활용]]:** `fork()` 후 즉시 `exec()`하는 경우 불필요한 복사를 완벽히 제거. (`vfork()`와 연관)

## 4. 페이지 교체 전략 (Page Replacement)

빈 프레임이 없을 때 **희생자 프레임(Victim Frame)**을 선정하여 내보내는(Swap-out) 정책.

### 4.1. 주요 알고리즘 비교

| **알고리즘**          | **설명**                      | **특징 및 장단점**                                                     |
| ----------------- | --------------------------- | ---------------------------------------------------------------- |
| **[[FIFO]]**      | 가장 먼저 들어온 페이지 교체            | 구현 간단. **Belady의 변이(Belady's Anomaly)** 발생 가능 (프레임을 늘려도 폴트가 증가). |
| **[[Optimal]]**   | 가장 오랫동안 안 쓰일 페이지 교체         | 이론상 최적. 미래를 알 수 없어 구현 불가 (성능 측정 기준점).                            |
| **[[LRU]]**       | 가장 오랫동안 사용 안 된 페이지 교체       | 과거 기록 기반(Locality). 성능 우수. 구현 비용 높음(Counter/Stack 필요).           |
| **Second-Chance** | FIFO + 참조 비트(Reference Bit) | LRU 근사. 기회를 한 번 더 줌(Clock 알고리즘). 참조 비트가 1이면 0으로 바꾸고 넘어감.         |

### 4.2. 개선된 2차 기회 (Enhanced Second-Chance)

_(참조 비트, 수정 비트)의 순서쌍을 이용_
- `(0, 0)`: 최근 사용 X, 수정 X $\rightarrow$ **최적의 교체 대상** (디스크 쓰기 불필요).
- `(0, 1)`: 최근 사용 X, 수정 O.
- `(1, 0)`: 최근 사용 O, 수정 X.
- `(1, 1)`: 최근 사용 O, 수정 O.

## 5. 시스템 안정성: 스래싱 (Thrashing)

### 5.1. 정의

프로세스가 페이지 교체(I/O)에만 시간을 쏟느라 CPU 이용률이 급격히 저하되는 현상.

- **원인:** 다중 프로그래밍 정도(MPD)가 너무 높아 각 프로세스가 필요한 최소 프레임도 확보하지 못함.
    

### 5.2. 방지 전략

- **지역성(Locality) 모델:** 프로세스는 특정 시점에 특정 페이지 집합만 집중적으로 참조함.
- **[[Working-Set Model]]**: 일정 시간($\Delta$) 동안 참조된 페이지 집합(Working Set)을 메모리에 유지. 전체 수요($D$) > 가용 메모리($m$)이면 프로세스 하나를 Suspend.
- **PFF (Page-Fault Frequency):** 페이지 폴트율 상한/하한을 두어 프레임을 동적으로 할당/회수.
    

### 5.3. 교체 범위

- **전역 교체 (Global):** 전체 메모리에서 경쟁 (처리량 $\uparrow$, 예측 가능성 $\downarrow$).
- **지역 교체 (Local):** 할당된 프레임 내에서만 교체 (성능 안정성 $\uparrow$).

## 6. 커널 메모리 할당 (Kernel Memory)

커널은 **연속된 메모리공간**(DMA 등)이 필요하며, 다양한 크기의 자료구조를 빈번히 생성/삭제함.

### 6.1. [[Buddy System]]

- 메모리를 $2^n$ 크기로 분할하여 할당.
- 해제 시 인접한 '버디'가 비어있으면 병합(Coalescing).
- **단점:** 내부 단편화(Internal Fragmentation).
    

### 6.2. [[Slab Allocation]]

- 자주 쓰이는 객체(예: `task_struct`)별로 미리 캐시(Cache) 생성.
- **장점:** 단편화 없음(`No Fragmentation`), 할당 속도 매우 빠름. (Linux 등에서 사용)
    

---

## 7. 실제 OS 사례

- **Solaris/BSD:** 실행 파일에서 직접 요구 페이징. 수정되지 않은 페이지는 스왑 아웃 없이 폐기(Discard), 수정된 페이지만 스왑 영역 사용.
    
- **Linux:** 커널 객체 관리에 **Slab Allocator** 적극 활용.

## 8. 결론: 설계 트레이드오프

> [!TIP] OS 설계 시 고려사항
> 
> 1. **복잡성 vs 성능:** LRU는 좋지만 비쌈 $\rightarrow$ Clock 알고리즘 같은 근사치 사용.
>     
> 2. **효율 vs 오버헤드:** PFF나 Working-Set은 스래싱을 막지만 관리 오버헤드가 있음.
>     
> 3. **처리량 vs 예측성:** 일반 시스템은 Global Replacement(처리량 중시), 실시간 시스템은 Local Replacement(예측성 중시) 선호.
