### 1. COW가 없는 경우 (비효율적인 방식)

`fork()`를 하는 순간 무조건 전체를 복사합니다.


```python
# 1. 부모 프로세스가 1GB 메모리를 사용 중이라고 가정
Parent_Memory = [Data_1, Data_2, ... Data_1GB] 

function fork_without_COW():
    # [비용 발생] 부모의 모든 데이터를 하나하나 다 복사함 (Deep Copy)
    Child_Memory = allocate_new_1GB()
    for i in range(0, 1GB):
        Child_Memory[i] = Parent_Memory[i]  # <-- 여기서 엄청난 시간 소요
    
    return Child_Process

function exec(new_program):
    # [낭비 발생] 방금 힘들게 복사한 Child_Memory를 싹 다 지움
    free(Child_Memory) 
    
    # 새로운 프로그램(예: ls)을 위해 새 메모리 할당
    load_new_program(new_program)
```

> **결과:** 1GB를 복사하는 `for` 루프를 기껏 돌렸는데, `exec` 함수가 시작되자마자 그 복사본을 휴지통에 버렸습니다. **완벽한 시간 낭비입니다.**

### 2. COW가 있는 경우 (효율적인 방식)

`fork()` 시점에는 복사하지 않고 '포인터'만 공유합니다.

```python
# 1. 부모 프로세스 메모리
Parent_Physical_Frames = [Frame_A, Frame_B, ...]

function fork_with_COW():
    # [비용 절감] 데이터를 복사하지 않음!
    # 자식의 페이지 테이블이 부모의 '물리 프레임'을 그대로 가리키게 함
    Child_Page_Table = Parent_Page_Table 
    
    # 중요: 부모와 자식 모두 해당 메모리를 '읽기 전용(Read-Only)'으로 설정
    set_permission(Parent_Page_Table, READ_ONLY)
    set_permission(Child_Page_Table, READ_ONLY)
    
    return Child_Process  # 복사 없이 순식간에 리턴

function exec(new_program):
    # 자식 프로세스는 아직 메모리에 '쓰기(Write)'를 하지 않았음.
    # 따라서 'Copy(복사)' 동작은 한 번도 일어나지 않은 상태.
    
    # 기존 공유(부모 프레임) 연결을 끊어버림 (데이터 복사 비용 0)
    discard_page_table(Child_Page_Table)
    
    # 새로운 프로그램을 위한 메모리를 새로 할당
    load_new_program(new_program)
```

> **결과:**
> 
> 1. `fork()` 할 때 데이터 복사 루프가 없었습니다. (빠름)
>     
> 2. `exec()` 할 때 기존 연결만 끊고 새 프로그램을 로드했습니다.
>     
> 3. **실제 데이터 복사(`memcpy`)는 단 1바이트도 일어나지 않았습니다.**
>

### 3. 비교 요약

만약 `fork()` 후에 `exec()`을 하지 않고, 자식 프로세스가 **데이터를 수정(Write)** 하려고 했다면?


```python
# exec() 없이 데이터를 수정하려 할 때 (이때 비로소 복사가 발생)
function handle_write_trap(page_number):
    # 하드웨어가 "어? 이거 Read-Only인데 왜 써?" 하고 Trap 발생
    
    # [이때 복사 수행] 수정하려는 '그 페이지만' 따로 복사
    new_frame = allocate_frame()
    copy_data(from=Parent_Frame, to=new_frame)
    
    # 자식 프로세스가 이제 이 새 프레임을 가리키게 하고 '쓰기 가능'으로 변경
    update_page_table(Child, page_number, new_frame, READ_WRITE)
```

하지만 **`fork()` -> `exec()`** 패턴에서는 위 `handle_write_trap` 함수가 호출될 틈도 없이 바로 `exec`으로 넘어가서 메모리를 교체해 버리기 때문에, **복사 비용이 '0'**이 되는 것입니다.
