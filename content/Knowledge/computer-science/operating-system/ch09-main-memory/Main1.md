# Memory Management – Background

- A program must be brought **from disk into memory** and placed **within a process** in order to be run.
- **Main memory** and **registers** are the only storage components that the **CPU can access directly**.
- The **memory unit** only sees a stream of:
  - addresses + **read requests**
  - address + **data** + **write requests**
- **Register access**
  - Completed in **one CPU clock cycle (or less)**
- **Main memory access**
  - May take **many CPU cycles**
  - Can cause a **CPU stall**
- **Cache**
  - Sits between **main memory** and **CPU registers**
- **Memory protection**
  - Is required to ensure **correct operation**

## Address Binding 
![ch09-main-memory-20251216205737959.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938164/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251216205737959.png)
### 1. Programs Waiting to Execute
Programs stored on disk and ready to be loaded into memory for execution are placed in an **input queue**.
- These programs must be **loaded into main memory** before they can run.
- **Without address-binding support**, a program would have to be loaded starting at **physical address 0000**.

### 2. Why Loading at Address 0000 Is a Problem
It is **inconvenient and impractical** for every user program to start at physical address 0000 because:
- Only **one program** could occupy that address at a time.
- Modern systems run **multiple processes simultaneously**.
- Memory must be **shared and relocated dynamically**.
    

> ❓ **How can a program avoid being loaded at address 0000?**  
> 👉 By using **address binding**, which allows programs to be relocated in memory.
### 3. Addresses Change During a Program’s Lifetime
A program’s addresses are represented **differently at different stages** of its life cycle.
#### (1) Source Code Stage — _Symbolic Addresses_
- Addresses are written as **symbols** (variable names, labels).
#### (2) Compilation Stage — _Relocatable Addresses
- The compiler translates symbolic addresses into **relocatable addresses**.    
- These addresses are expressed **relative to the start of the program or module**.
Example:
- “14 bytes from the beginning of this module”
This means:
* The exact memory location is **not yet fixed**.
#### (3) Linking / Loading Stage — _Absolute Addresses_
- The **linker or loader** converts relocatable addresses into **absolute physical addresses**.
- Example:
    - Relocatable address → **Absolute address 74014**
At this point, the program can be placed **anywhere in memory**.

# Logical vs. [[Physical Address Space]]
The concept of a logical address space that is bound to a separate physical address space is central to proper memory management 
	• **Logical address** – generated by the **CPU**; also referred to as virtual address 
	• **Physical address** – address seen by the **memory** unit

- **컴파일 시간 (Compile-time) & 적재 시간 (Load-time) 바인딩:**
    - 논리 주소와 물리 주소가 **동일**합니다.
- **실행 시간 (Execution-time) 바인딩:**
    - 논리 주소(가상 주소)와 물리 주소가 **다릅니다**.

# Dynamic Linking (동적 연결)

## 1. Static Linking (정적 연결)
* System libraries and program code combined by the loader into the binary program image
  * 시스템 라이브러리와 프로그램 코드가 로더에 의해 하나의 이진(binary) 프로그램 이미지로 결합됩니다.
## 2. Dynamic Linking (동적 연결)
* Linking postponed until execution time
  * 연결(Linking) 과정이 프로그램 실행 시간까지 연기됩니다.
### The Stub Mechanism (스텁 메커니즘)
* Small piece of code, stub, used to locate the appropriate memory-resident library routine
  * '스텁(Stub)'이라는 작은 코드 조각이 메모리에 상주하고 있는 적절한 라이브러리 루틴을 찾는 데 사용됩니다.
* Stub replaces itself with the address of the routine, and executes the routine
  * 스텁은 자기 자신을 해당 루틴의 메모리 주소로 대체하고, 그 루틴을 실행합니다.

### OS Role (운영체제의 역할)
* Operating system checks if routine is in processes’ memory address
  * 운영체제는 해당 루틴이 현재 프로세스의 메모리 주소 공간에 있는지 확인합니다.
  * If not in address space, add to address space
    * 만약 주소 공간에 없다면, 이를 추가합니다(메모리에 적재).

## 3. Characteristics (특징 및 활용)
* Dynamic linking is particularly useful for libraries
  * 동적 연결은 라이브러리를 사용할 때 특히 유용합니다.
* System also known as shared libraries
  * 이 시스템은 '공유 라이브러리(Shared Libraries)'라고도 알려져 있습니다. (예: Windows의 .dll, Linux의 .so)
* Consider applicability to patching system libraries
  * 시스템 라이브러리를 패치(업데이트)할 때의 적용 가능성을 고려해야 합니다.
  * Versioning may be needed
    * (라이브러리 업데이트 시 호환성 문제 등을 해결하기 위해) 버전 관리(Versioning)가 필요할 수 있습니다.

# Contiguous Allocation (연속 할당)

## Necessity of Memory Allocation (메모리 할당의 필요성)
* Main memory must support both OS and user processes
  * 메인 메모리는 운영체제(OS)와 사용자 프로세스를 모두 수용(지원)해야 합니다.
* Limited resource, must allocate efficiently
  * 메모리는 한정된 자원이므로, 효율적으로 할당해야 합니다.

## Contiguous Allocation Method (연속 할당 기법)
* Contiguous allocation is one early method
  * 연속 할당은 초기에 사용된 메모리 관리 방법 중 하나입니다.
* Main memory usually into two partitions:
  * 메인 메모리는 보통 두 개의 영역(파티션)으로 나뉩니다.

### Memory Partitions (메모리 파티션)
* [[==Resident operating system==]], usually held in low memory with interrupt vector
  * 상주 운영체제(Resident OS)는 보통 인터럽트 벡터와 함께 하위 메모리(Low Memory)에 위치합니다.
* User processes then held in high memory
  * 사용자 프로세스들은 상위 메모리(High Memory)에 위치합니다.
* Each process contained in single contiguous section of memory
  * 각 프로세스는 메모리 내의 연속적인 단일 섹션(구역)에 포함됩니다. (즉, 조각나지 않고 한 덩어리로 할당됩니다.)


## Protection Mechanism (보호 메커니즘)
* Relocation registers used to protect user processes from each other, and from changing operating-system code and data
  재배치 레지스터는 사용자 프로세스들이 서로의 영역을 침범하지 못하게 보호하고, 운영체제 코드와 데이터가 변경되지 않도록 보호하는 데 사용됩니다.

## Register Definitions (레지스터의 정의)
* Base register contains value of smallest physical address
  기준(Base) 레지스터는 할당된 메모리 공간의 가장 작은 물리 주소 값을 담고 있습니다. (시작점)
* Limit register contains range of logical addresses – each logical address must be less than the limit register
  한계(Limit) 레지스터는 논리 주소 공간의 범위(크기)를 담고 있습니다. 모든 논리 주소는 이 한계 레지스터 값보다 작아야 합니다.

## Dynamic Mapping & Flexibility (동적 매핑과 유연성)
* MMU maps logical address dynamically
  MMU(메모리 관리 장치)는 실행 시간에 논리 주소를 물리 주소로 동적으로 매핑(변환)합니다.
* Can then allow actions such as kernel code being transient and kernel changing size
  이러한 동적 매핑 덕분에 커널 코드가 일시적으로만 상주하거나(transient), 커널의 크기가 유동적으로 변하는 것이 가능해집니다.

# Variable Partition (가변 분할)

## Multiple-partition Allocation (다중 분할 할당)
* Multiple-partition allocation
  * 다중 분할 할당 기법을 사용합니다.
* Degree of multiprogramming limited by number of partitions
  * 다중 프로그래밍의 정도(동시에 실행 가능한 프로세스의 수)는 파티션의 개수에 의해 제한됩니다.

## Variable-partition Concept (가변 분할의 개념)
* Variable-partition sizes for efficiency (sized to a given process’ needs)
  * 효율성을 위해 파티션의 크기를 고정하지 않고 가변적으로 설정합니다. (각 프로세스가 필요로 하는 크기에 딱 맞춰서 할당됩니다.)
* ==**Hole**== – block of available memory; holes of various size are scattered throughout memory
  * 홀(Hole)은 사용 가능한 빈 메모리 블록을 의미하며, 다양한 크기의 홀들이 메모리 전체에 흩어져 존재합니다.


## Allocation Process (할당 및 해제 과정)
* When a process arrives, it is allocated memory from a hole large enough to accommodate it
  * 새로운 프로세스가 도착하면, 그 프로세스를 수용하기에 충분히 큰 홀을 찾아 메모리를 할당합니다.
* Process exiting frees its partition, ==adjacent free partitions combined==
  * 프로세스가 종료되어 메모리를 반납할 때, 만약 바로 옆에 비어 있는 파티션(홀)이 있다면 이들을 하나로 합칩니다. (더 큰 홀을 만들기 위함)

## OS Management (운영체제의 관리)
* Operating system maintains information about: a) allocated partitions b) free partitions (hole)
  * 운영체제는 다음 두 가지 정보를 유지 및 관리합니다: a) 이미 할당된 파티션, b) 비어 있는 파티션(홀).

# Dynamic Storage-Allocation Problem (동적 저장장치 할당 문제)

## Problem Definition (문제 정의)
* How to satisfy a request of size n from a list of free holes?
  * 자유 공간 리스트(Free holes list)에서 크기 n인 요청을 어떻게 충족시킬 것인가?

## Allocation Strategies (할당 전략)
* **==First-fit==**: Allocate the first hole that is big enough
  * 최초 적합(First-fit): 요청을 수용할 수 있는(충분히 큰) 첫 번째 홀을 할당합니다.
* ==**Best-fit**==: Allocate the smallest hole that is big enough; must search entire list, unless ordered by size
  * 최적 적합(Best-fit): 요청을 수용할 수 있는 홀 중에서 가장 작은 홀을 할당합니다. (리스트가 크기순으로 정렬되어 있지 않다면 전체를 검색해야 합니다.)
  * Produces the smallest leftover hole
    * 가장 작은 크기의 남는 홀(자투리 공간)을 생성합니다.
* **==Worst-fit==**: Allocate the largest hole; must also search entire list
  * 최악 적합(Worst-fit): 가장 큰 홀을 할당합니다. (역시 리스트 전체를 검색해야 합니다.)
  * Produces the largest leftover hole
    * 가장 큰 크기의 남는 홀을 생성합니다. (남은 공간이 커서 다른 프로세스가 사용할 가능성이 있습니다.)

## Comparison (비교)
* First-fit and best-fit better than worst-fit in terms of speed and storage utilization
  * 속도와 저장 공간 이용률 측면에서 최초 적합과 최적 적합이 최악 적합보다 더 우수합니다.

# Fragmentation (단편화)

## Types of Fragmentation (단편화의 종류)

* External Fragmentation – total memory space exists to satisfy a request, but it is not contiguous
  * 외부 단편화: 요청을 충족할 만큼의 전체 메모리 공간은 존재하지만, 연속적이지 않아서 할당할 수 없는 상태입니다.
* Internal Fragmentation – allocated memory may be slightly larger than requested memory; this size difference is memory internal to a partition, but not being used
  * 내부 단편화: 할당된 메모리가 요청된 메모리보다 약간 더 큰 경우입니다. 이 크기 차이는 파티션 내부의 공간이지만 사용되지 않고 낭비됩니다.

## The 50-percent Rule (50% 규칙)
* First fit analysis reveals that given N blocks allocated, 0.5 N blocks lost to fragmentation
  * 최초 적합(First fit) 분석에 따르면, N개의 블록이 할당되었을 때 0.5N개의 블록이 단편화로 인해 손실됩니다.
  * 1/3 may be unusable -> 50-percent rule
    * 전체 메모리의 1/3이 사용 불가능할 수 있다는 의미로, 이를 50% 규칙이라 부릅니다.

## Compaction (압축)
* Reduce external fragmentation by compaction
  * 압축(Compaction)을 통해 외부 단편화를 줄일 수 있습니다.
  * Shuffle memory contents to place all free memory together in one large block
    * 메모리의 모든 내용을 한쪽으로 몰아서(Shuffle), 흩어진 빈 공간들을 하나의 큰 블록으로 합치는 작업입니다.
* Compaction is possible only if relocation is dynamic, and is done at execution time
  * 압축은 재배치(Relocation)가 동적이며, 실행 시간(Execution time)에 이루어지는 경우에만 가능합니다.

## I/O Problems with Compaction (압축 시 I/O 문제)
* I/O problem
  * 입출력(I/O) 관련 문제가 발생할 수 있습니다. (I/O 작업 중에 메모리 위치가 바뀌면 엉뚱한 곳에 데이터가 쓰일 수 있음)
* Solution
	* 1. **Latch job** in memory while it is involved in I/O
		* I/O 작업에 관여된 프로세스는 메모리 내에서 이동하지 못하도록 고정(Latch)시켜야 합니다.
	* 2. Do I/O only into **OS buffers**
		* 또는 I/O를 오직 운영체제 버퍼(OS buffers)로만 수행하게 하고, 이후 사용자 메모리로 복사하는 방식을 씁니다.

## Backing Store Issue (보조 저장장치 이슈)
* Now consider that backing store has same fragmentation problems
  * 보조 저장장치(Backing store, 스왑 영역 등) 또한 동일한 단편화 문제를 겪을 수 있음을 고려해야 합니다.

# Paging (페이징)

## Basic Concept (기본 개념)
* Physical address space of a process can be noncontiguous; process is allocated physical memory whenever the latter is available
  * 프로세스의 물리 주소 공간이 연속적일 필요가 없습니다. 물리 메모리의 어느 위치든 사용 가능하면 프로세스에 할당됩니다.
  => Avoids external fragmentation
    * 이를 통해 외부 단편화 문제를 피할 수 있습니다.
  => Avoids problem of varying sized memory chunks
    * 가변 크기의 메모리 덩어리를 처리해야 하는 문제도 피할 수 있습니다.

## Frames and Pages (프레임과 페이지)
* Divide physical memory into fixed-sized blocks called frames
  * 물리 메모리를 프레임(Frames)이라고 불리는 고정 크기 블록으로 나눕니다.
  * Size is power of 2, between 512 bytes and 16 Mbytes
    * 프레임 크기는 2의 거듭제곱 형태이며, 보통 512 바이트에서 16 메가바이트 사이입니다.
* Divide logical memory into blocks of same size called pages
  * 논리 메모리를 프레임과 동일한 크기의 블록으로 나누며, 이를 페이지(Pages)라고 부릅니다.

## Implementation Mechanism (구현 메커니즘)
* Keep track of all free frames
  * 운영체제는 모든 빈 프레임(Free frames)을 추적(관리)합니다.
* To run a program of size N pages, need to find N free frames and load program
  * N 페이지 크기의 프로그램을 실행하려면, N개의 빈 프레임을 찾아 프로그램을 적재해야 합니다.
* Set up a page table to translate logical to physical addresses
  * 논리 주소를 물리 주소로 변환하기 위해 페이지 테이블(Page table)을 설정합니다.
* Backing store likewise split into pages
  * 보조 저장장치 또한 페이지 단위로 나누어 관리합니다.
* Still have Internal fragmentation
  * 페이징 기법을 사용하더라도 여전히 내부 단편화 문제는 존재합니다. (마지막 페이지가 꽉 차지 않을 경우)

# Address Translation Scheme (주소 변환 체계)

## Components of Address (주소의 구성요소)
![ch09-main-memory-20251216205738263.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938167/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251216205738263.png)

* Address generated by CPU is divided into:
  * CPU가 생성하는 주소는 다음 두 부분으로 나뉩니다.
* Page number (p) – used as an index into a page table which contains base address of each page in physical memory
  * 페이지 번호(p): 페이지 테이블의 인덱스로 사용됩니다. 페이지 테이블에는 물리 메모리에 있는 각 페이지의 시작 주소(Base address)가 들어있습니다.
* Page offset (d) – combined with base address to define the physical memory address that is sent to the memory unit
  * 페이지 오프셋(d): 페이지 내부의 변위입니다. 페이지 테이블에서 얻은 시작 주소와 결합되어, 메모리 유닛으로 보내질 최종 물리 메모리 주소를 정의합니다.

## Address Space Calculation (주소 공간 계산)
* For given logical address space 2^m and page size 2^n
  * 논리 주소 공간의 크기가 2^m이고, 페이지 크기가 2^n인 경우를 가정합니다. (m: 전체 주소 비트 수, n: 오프셋 비트 수)

## Calculating internal fragmentation

### Calculation Example (계산 예시)
* Page size = 2,048 bytes
  페이지 크기는 2,048바이트라고 가정합니다.
* Process size = 72,766 bytes
  프로세스의 크기는 72,766바이트입니다.
* 35 pages + 1,086 bytes
  계산해보면 35개의 온전한 페이지가 필요하고, 1,086바이트가 남습니다. (즉, 36번째 페이지의 일부를 사용합니다.)
  (계산식: 72,766 = 35 × 2,048 + 1,086)
* Internal fragmentation of 2,048 - 1,086 = 962 bytes
  따라서 내부 단편화(낭비되는 공간)는 2,048 - 1,086 = 962바이트가 발생합니다.

### General Case Analysis (일반적인 경우의 분석)
* Worst case fragmentation = 1 frame – 1 byte
  단편화가 가장 심하게 발생하는 최악의 경우는 1 프레임 크기에서 딱 1바이트가 빠질 때입니다. (새 페이지를 할당받아 1바이트만 쓰고 나머지를 다 버리는 경우)
* On average fragmentation = 1 / 2 frame size
  평균적으로는 프레임 크기의 절반(1/2) 정도가 단편화로 발생한다고 봅니다.

## Page Size Trade-offs & Trends (페이지 크기의 트레이드오프와 추세)
* So small frame sizes desirable?
  그렇다면 (내부 단편화를 줄이기 위해) 작은 프레임 크기가 바람직할까요?
* But each page table entry takes memory to track
  하지만 페이지가 작아지면 페이지 개수가 늘어나고, 이를 관리하기 위한 각 페이지 테이블 항목(Entry) 자체가 메모리를 차지하게 됩니다. (오버헤드 증가)
* Page sizes growing over time
  시간이 지날수록 메모리 용량이 커짐에 따라 페이지 크기도 커지는 추세입니다.
* Solaris supports two page sizes – 8 KB and 4 MB

# Implementation of Page Table (페이지 테이블의 구현)

## Memory Access Issue (메모리 접근 문제)

* Page table is kept in main memory
  페이지 테이블은 메인 메모리에 보관됩니다.
* ==Page-table base register (PTBR)== points to the page table
  페이지 테이블 기준 레지스터(PTBR)는 페이지 테이블을 가리킵니다. (테이블의 시작 주소 저장)
* ==Page-table length register (PTLR)== indicates size of the page table
  페이지 테이블 길이 레지스터(PTLR)는 페이지 테이블의 크기를 나타냅니다.
* In this scheme every data/instruction access requires two memory accesses
  이 방식(레지스터만 사용하는 방식)에서는 모든 데이터나 명령어 접근 시 두 번의 메모리 접근이 필요합니다.
* One for the page table and one for the data / instruction
  한 번은 (주소 변환을 위해) 페이지 테이블에 접근하고, 다른 한 번은 실제 데이터나 명령어를 가져오기 위해 접근합니다.

## The Solution: TLB (해결책: TLB)

* The two-memory access problem can be solved by the use of a special fast-lookup hardware cache called ==translation look-aside buffers (TLBs)== (also called associative memory).
  이러한 두 번의 메모리 접근 문제는 변환 색인 버퍼(TLB)라고 불리는 특별한 고속 하드웨어 캐시를 사용하여 해결할 수 있습니다. (연관 메모리라고도 불립니다.)

# Translation Look-Aside Buffer (TLB) (변환 색인 버퍼)

## ASIDs and Protection (ASID와 보호)
* Some TLBs store [[address-space identifiers (ASIDs)]] in each TLB entry – uniquely identifies each process to provide address-space protection for that process
  일부 TLB는 각 항목에 주소 공간 식별자(ASID)를 저장합니다. 이는 각 프로세스를 고유하게 식별하여 해당 프로세스에 대한 주소 공간 보호를 제공합니다.
* Otherwise need to flush at every context switch
  만약 ASID가 없다면 문맥 교환(Context switch)이 일어날 때마다 TLB를 비워야(Flush) 합니다. (이전 프로세스의 주소 변환 정보가 남아있으면 안 되기 때문입니다.)

## TLB Management (TLB 관리)
* TLBs typically small (64 to 1,024 entries)
  TLB는 보통 작습니다(64개에서 1,024개 항목 정도).
* On a TLB miss, ==value is loaded== into the TLB for faster access next time
  TLB 미스(TLB에 찾는 정보가 없음)가 발생하면, 페이지 테이블에서 정보를 가져오면서 그 값을 TLB에 적재합니다. 이는 다음번에 빠르게 접근하기 위함입니다.
* ==Replacement policies== must be considered
  TLB가 꽉 찼을 때 어떤 항목을 지울지 결정하는 교체 정책(Replacement policies)을 고려해야 합니다.
* [[Some entries]] can be wired down for permanent fast access
  일부 항목(예: 중요한 커널 코드)은 영구적인 빠른 접근을 위해 고정(wired down)될 수 있습니다. (교체되지 않음)

# Effective Access Time (유효 접근 시간)

## Basic Concepts (기본 개념)
* Hit ratio – percentage of times that a page number is found in the TLB
  적중률(Hit ratio) – 페이지 번호가 TLB에서 발견되는 횟수의 비율입니다.
* An 80% hit ratio means that we find the desired page number in the TLB 80% of the time.
  80%의 적중률은 우리가 원하는 페이지 번호를 TLB에서 80%의 확률로 찾는다는 것을 의미합니다.
## Scenario Assumptions (시나리오 가정)
* Suppose that 10 nanoseconds to access memory.
  메모리에 접근하는 데 10나노초(ns)가 걸린다고 가정해 봅시다.
* If we find the desired page in TLB then a mapped-memory access take 10 ns
  만약 원하는 페이지를 TLB에서 찾는다면(Hit), 매핑된 메모리 접근에는 10ns가 소요됩니다. (TLB 접근 시간은 무시하거나 포함됨을 가정)
* Otherwise we need two memory access so it is 20 ns
  그렇지 않다면(Miss), 두 번의 메모리 접근(페이지 테이블 조회 + 실제 데이터 접근)이 필요하므로 20ns가 소요됩니다.

## Calculation Examples (계산 예시)
* Effective Access Time (EAT) calculation
  유효 접근 시간(EAT) 계산은 다음과 같습니다.
* EAT = 0.80 x 10 + 0.20 x 20 = 12 nanoseconds implying 20% slowdown in access time
  EAT = 0.80 x 10 + 0.20 x 20 = 12 나노초이며, 이는 메모리 접근 속도가 20% 느려짐을 의미합니다.
* Consider a more realistic hit ratio of 99%, EAT = 0.99 x 10 + 0.01 x 20 = 10.1ns implying only 1% slowdown in access time.
  더 현실적인 적중률인 99%를 고려하면, EAT = 0.99 x 10 + 0.01 x 20 = 10.1ns가 되며, 이는 접근 속도가 단 1%만 느려짐을 의미합니다.

# Memory Protection (메모리 보호)

## Protection Bits (보호 비트)
* Memory protection implemented by associating protection bit with each frame to indicate if read-only or read-write access is allowed
  메모리 보호는 각 프레임에 보호 비트를 연결하여 읽기 전용(read-only)인지 읽기-쓰기(read-write) 접근이 허용되는지 표시함으로써 구현됩니다.
* Can also add more bits to indicate page execute-only, and so on
  실행 전용(execute-only) 페이지 등을 표시하기 위해 더 많은 비트를 추가할 수도 있습니다.
![ch09-main-memory-20251216205738637.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938172/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251216205738637.png)
## Valid-Invalid Bit (유효-무효 비트)
* Valid-invalid bit attached to each entry in the page table:
  페이지 테이블의 각 항목(Entry)에는 유효-무효 비트가 붙어 있습니다.
* "valid" indicates that the associated page is in the process’ logical address space, and is thus a legal page
  "valid(유효)"는 해당 페이지가 프로세스의 논리 주소 공간에 존재하며, 따라서 합법적인(접근 가능한) 페이지임을 나타냅니다.
* "[[invalid]]" indicates that the page is not in the process’ logical address space
  "invalid(무효)"는 해당 페이지가 프로세스의 논리 주소 공간에 속하지 않음을 나타냅니다.

## Alternative & Violation Handling (대안 및 위반 처리)
* Or use page-table length register (PTLR)
  또는 페이지 테이블 길이 레지스터(PTLR)를 사용하여 (유효한 주소 범위를 제한하는 방식으로) 보호할 수도 있습니다.
* Any violations result in a trap to the kernel
  이러한 보호 규칙을 위반하는 모든 시도는 커널로의 트랩(Trap, 예외 발생)을 유발합니다.

## Shared Code (공유 코드)
* One copy of read-only (reentrant) code shared among processes (i.e., text editors, compilers, window systems)
  읽기 전용(재진입 가능) 코드의 사본 하나를 여러 프로세스들 사이에서 공유합니다. (예: 텍스트 에디터, 컴파일러, 윈도우 시스템 등)
* Similar to multiple threads sharing the same process space
  이는 마치 여러 스레드가 동일한 프로세스 공간을 공유하는 것과 유사한 개념입니다.
* Also useful for interprocess communication if sharing of read-write pages is allowed
  만약 읽기-쓰기(read-write) 페이지의 공유가 허용된다면, 프로세스 간 통신(IPC)을 위해서도 유용하게 사용될 수 있습니다.

* Each process keeps a separate copy of the code and data

* The pages for the private code and data can appear anywhere in the logical address space
  이러한 사유 코드와 데이터를 담은 페이지들은 논리 주소 공간의 어디에든 위치할 수 있습니다.

# Structure of the Page Table (페이지 테이블의 구조)

## The Size Problem (크기 문제)
* Memory structures for paging can get huge using straight-forward methods
  단순한 방법을 사용하면 페이징을 위한 메모리 구조가 매우 커질 수 있습니다.
* Consider a 32-bit logical address space as on modern computers
  현대 컴퓨터와 같은 32비트 논리 주소 공간을 고려해 봅시다.
* Page size of 4 KB (2^12)
  페이지 크기는 4KB(2의 12승)입니다.
* Page table would have 1 million entries ([[2^32]] / 2^12)
  (계산해보면) 페이지 테이블은 약 100만 개의 항목(2의 32승 나누기 2의 12승)을 갖게 됩니다.
* If each entry is 4 bytes -> each process 4 MB of physical address space for the page table alone
  만약 각 항목이 4바이트라면, 각 프로세스는 페이지 테이블을 위해서만 4MB의 물리 주소 공간이 필요하게 됩니다.

## Allocation Issues & Solutions (할당 문제와 해결책)
* Don’t want to allocate that contiguously in main memory
  우리는 이 공간(거대해진 페이지 테이블)을 메인 메모리에 연속적으로 할당하고 싶지 않습니다. (큰 연속 공간을 찾기 힘들기 때문입니다.)
* One simple solution is to ==divide the page table into smaller units==
  한 가지 간단한 해결책은 페이지 테이블을 더 작은 단위로 나누는 것입니다.
	* Hierarchical Paging
	  계층적 페이징
	* Hashed Page Tables
	  해시 페이지 테이블
	* Inverted Page Tables
	  역 페이지 테이블

# Hashed Page Tables (해시 페이지 테이블)
![ch09-main-memory-20251216235131817.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938179/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251216235131817.png)

* Common in address spaces > 32 bits
  32비트보다 큰 주소 공간에서 흔히 사용됩니다.
* The virtual page number is hashed into a page table
  가상 페이지 번호가 해싱되어 페이지 테이블로 들어갑니다.
* This page table contains a chain of elements hashing to the same location
  [[이 페이지 테이블은 동일한 위치로 해싱되는 요소들의 체인(연결 리스트)을 포함합니다.]]
* Each element contains (1) the virtual page number (2) the value of the mapped page frame (3) a pointer to the next element
  각 요소는 ==(1) 가상 페이지 번호, (2) 매핑된 페이지 프레임 값, (3) 다음 요소를 가리키는 포인터==를 포함합니다.
* Virtual page numbers are compared in this chain searching for a match
  일치하는 것을 찾기 위해 이 체인에서 가상 페이지 번호들을 비교하며 탐색합니다.
* If a match is found, the corresponding physical frame is extracted
  만약 일치하는 것을 찾으면, 그에 해당하는 물리 프레임을 추출합니다.


## Variation: Clustered Page Tables (변형: 클러스터 페이지 테이블)

* Variation for 64-bit addresses is clustered page tables
  64비트 주소를 위한 변형으로 클러스터 페이지 테이블이 있습니다.
* Similar to hashed but each entry refers to several pages (such as 16) rather than 1
  해시 테이블과 유사하지만 각 항목이 1개가 아닌 여러 개의 페이지(예: 16개)를 가리킵니다.
* Especially useful for sparse address spaces (where memory references are non-contiguous and scattered)
  [[희소 주소 공간(메모리 참조가 연속적이지 않고 흩어져 있는 경우)]]에 특히 유용합니다.

# Inverted Page Table (역 페이지 테이블)
![ch09-main-memory-20251217000131557.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938180/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217000131557.png)
* Rather than each process having a page table and keeping track of all possible logical pages, track all physical pages
  각 프로세스가 페이지 테이블을 가지고 모든 가능한 논리 페이지를 추적하는 대신, 모든 물리 페이지를 추적합니다.
* One entry for each real page of memory
  메모리의 각 실제 페이지(프레임)마다 하나의 항목(Entry)이 존재합니다.
* Entry consists of the virtual address of the page stored in that real memory location, with information about the process that owns that page
  각 항목은 그 실제 메모리 위치에 저장된 페이지의 ==가상 주소==와 그 ==페이지를 소유한 프로세스에 대한 정보(PID== 등)로 구성됩니다.
* Decreases memory needed to store each page table, but increases time needed to search the table when a page reference occurs
  각 페이지 테이블을 저장하는 데 필요한 메모리는 줄어들지만, 페이지 참조가 발생했을 때 테이블을 검색하는 데 걸리는 시간은 증가합니다.
###  Optimization & Issue (최적화 및 문제점)
* Use hash table to limit the search to one — or at most a few — pagetable entries
  (검색 시간을 줄이기 위해) 검색을 하나 또는 최대 몇 개의 페이지 테이블 항목으로 제한하도록 해시 테이블을 사용합니다.
* TLB can accelerate access
  TLB를 사용하여 접근을 가속화할 수 있습니다.
* But how to implement shared memory?
  하지만 공유 메모리는 어떻게 구현할까요? (역 페이지 테이블의 단점)
* One mapping of a virtual address to the shared physical address
  가상 주소에서 공유 물리 주소로의 매핑은 하나만 존재하게 됩니다. (물리 프레임 하나당 항목이 하나뿐이므로 여러 가상 주소를 매핑하기 어렵습니다.)

# Swapping (스와핑)
![ch09-main-memory-20251217000531198.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938181/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217000531198.png)
## Basic Concept (기본 개념)
* A process can be swapped temporarily out of memory to a backing store, and then brought back into memory for continued execution
  프로세스는 일시적으로 메모리에서 보조 저장장치(Backing store)로 쫓겨났다가(Swapped out), 나중에 실행을 계속하기 위해 다시 메모리로 돌아올(Swapped in) 수 있습니다.
* Total physical memory space of processes can exceed physical memory
  이 과정을 통해 프로세스들이 사용하는 전체 물리 메모리 공간의 합이 실제 물리 메모리 크기를 초과할 수 있습니다.

## Backing Store (보조 저장장치)
* Backing store – fast disk large enough to accommodate copies of all memory images for all users; must provide direct access to these memory images
  보조 저장장치(스왑 영역)는 모든 사용자의 메모리 이미지 사본을 수용할 만큼 충분히 크고 빠른 디스크여야 하며, 이러한 메모리 이미지에 대한 직접 접근(Direct access)을 제공해야 합니다.

## Swapping Mechanism (스와핑 메커니즘)
* Roll out, roll in – swapping variant used for priority-based scheduling algorithms; lower-priority process is swapped out so higher-priority process can be loaded and executed
  롤아웃/롤인(Roll out, roll in)은 우선순위 기반 스케줄링 알고리즘에서 사용되는 스와핑의 변형입니다. 더 높은 우선순위의 프로세스를 적재하고 실행하기 위해 낮은 우선순위의 프로세스를 스왑 아웃(Roll out)시킵니다.
* Major part of swap time is transfer time; total transfer time is directly proportional to the amount of memory swapped
  스왑 시간의 대부분은 전송 시간(Transfer time)이 차지하며, 총 전송 시간은 스왑되는 메모리의 양에 정비례합니다.
* System maintains a ready queue of ready-to-run processes which have memory images on disk
  시스템은 디스크에 메모리 이미지를 가지고 있는, 실행 준비가 된 프로세스들의 준비 큐(Ready queue)를 유지 관리합니다.

## Swapping Considerations & Variations (스와핑 고려사항 및 변형)
* Does the swapped out process need to swap back in to same physical addresses?
  스왑 아웃된 프로세스가 다시 스왑 인될 때 반드시 원래 있던 동일한 물리 주소로 돌아와야 할까요?
	* Depends on address binding method
	  그것은 주소 바인딩(Address binding) 방식에 따라 다릅니다. (실행 시간 바인딩이라면 다른 주소로 와도 됩니다.)
	* Plus consider pending I/O to / from process memory space
	  또한, 프로세스 메모리 공간 입출력(I/O) 작업이 보류 중인 상태도 고려해야 합니다. (I/O 작업 중에 스왑 아웃되면 문제 발생 가능)
	* Modified versions of swapping are found on many systems (i.e., UNIX, Linux, and Windows)
	  많은 시스템(UNIX, Linux, Windows 등)에서 변형된 형태의 스와핑을 볼 수 있습니다.
		* Swapping normally disabled
		  보통 스와핑은 비활성화되어 있습니다.
		* Started if more than threshold amount of memory allocated
		  할당된 메모리 양이 임계값(Threshold)을 초과하면 스와핑이 시작됩니다.
		* Disabled again once memory demand reduced below threshold
		  메모리 수요가 다시 임계값 아래로 줄어들면 스와핑은 다시 비활성화됩니다.
![ch09-main-memory-20251217000531198.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938181/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217000531198.png)

# Context Switch Time including Swapping (스와핑을 포함한 문맥 교환 시간)

## The High Cost of Swapping (스와핑의 높은 비용)
* If next processes to be put on CPU is not in memory, need to swap out a process and swap in target process
  만약 CPU에 할당될 다음 프로세스가 메모리에 없다면, 현재 메모리에 있는 프로세스 중 하나를 스왑 아웃하고 목표 프로세스를 스왑 인해야 합니다.
* Context switch time can then be very high
  이 경우 문맥 교환 시간이 매우 길어질 수 있습니다.

## Calculation Example (계산 예시)
* 100MB process swapping to hard disk with transfer rate of 50MB/sec
  전송 속도가 초당 50MB인 하드 디스크로 100MB 크기의 프로세스를 스와핑한다고 가정해 봅시다.
* Swap out time of 2000 ms
  스왑 아웃하는 데 2000ms(2초)가 걸립니다. (100MB / 50MB/sec = 2sec)
* Plus swap in of same sized process
  여기에 같은 크기의 프로세스를 스왑 인하는 시간도 더해야 합니다.
* Total context switch swapping component time of 4000ms (4 seconds)
  따라서 문맥 교환에서 스와핑 요소가 차지하는 총 시간은 4000ms(4초)가 됩니다.

## Optimization (최적화)
* Can reduce if reduce size of memory swapped – by knowing how much memory really being used
  실제로 사용되고 있는 메모리의 양을 알면 스왑되는 메모리의 크기를 줄여서 이 시간을 단축할 수 있습니다.
* System calls to inform OS of memory use via `request_memory()` and `release_memory()`
  `request_memory()`와 `release_memory()` 같은 시스템 호출을 통해 운영체제에 메모리 사용 정보를 알릴 수 있습니다.

## Constraints on Swapping (스와핑의 제약 조건)
* Other constraints as well on swapping
  스와핑에는 다른 제약 조건들도 있습니다.
* Pending I/O – can’t swap out as I/O would occur to wrong process
  보류 중인 I/O(Pending I/O)가 있는 경우, I/O 작업이 엉뚱한 프로세스의 메모리 공간에서 발생할 수 있으므로 스왑 아웃할 수 없습니다.
* Or always transfer I/O to kernel space, then to I/O device
  또는 I/O 데이터를 항상 커널 공간으로 먼저 전송한 다음 I/O 장치로 보내는 방법을 사용합니다.
* Known as double buffering, adds overhead
  이를 ==이중 버퍼링(Double buffering)==이라고 하며, 오버헤드가 추가됩니다.

## Modern Usage (현대의 사용 방식)
* Standard swapping not used in modern operating systems
  현대 운영체제에서는 표준 스와핑 방식이 사용되지 않습니다.
* But modified version common
  하지만 변형된 버전이 흔히 사용됩니다.
* Swap only when free memory extremely low
  (변형된 버전에서는) 자유 메모리가 극도로 부족할 때만 스와핑을 수행합니다.

# Swapping on Mobile Systems (모바일 시스템에서의 스와핑)

## Limitations of Swapping (스와핑의 한계)
* Not typically supported
  일반적으로 지원되지 않습니다.
* Flash memory based
  플래시 메모리 기반이기 때문입니다.
* Small amount of space
  공간 용량이 적습니다.
* Limited number of write cycles
  쓰기 횟수가 제한적입니다. (수명 문제)
* Poor throughput between flash memory and CPU on mobile platform
  모바일 플랫폼에서는 플래시 메모리와 CPU 사이의 처리량(Throughput)이 좋지 않습니다.
* Instead use other methods to free memory if low
  대신 메모리가 부족할 경우 다른 방법을 사용하여 메모리를 확보합니다.
* iOS asks apps to voluntarily relinquish allocated memory
  iOS는 앱에게 할당된 메모리를 자발적으로 포기하도록 요청합니다.
* Read-only data thrown out and reloaded from flash if needed
  읽기 전용 데이터는 버려지고, 필요할 때 플래시 메모리에서 다시 로드됩니다.
* Failure to free can result in termination
  메모리 확보에 실패하면 앱이 강제 종료될 수 있습니다.
* Android terminates apps if low free memory, but first writes application state to flash for fast restart
  Android는 자유 메모리가 부족하면 앱을 강제 종료시키지만, 빠른 재시작을 위해 먼저 애플리케이션 상태를 플래시 메모리에 기록합니다.
* Both OSes support paging as discussed below

# Example: The Intel IA-32 Architecture (IA-32 아키텍처)
## Memory Management Support (메모리 관리 지원)
* Supports both segmentation and segmentation with paging
  순수 세그멘테이션과 '페이징을 곁들인 세그멘테이션' 두 가지 방식을 모두 지원합니다.
* Each segment can be 4 GB
  각 세그먼트의 크기는 최대 4GB까지 가능합니다.
* Up to 16 K segments per process
  프로세스당 최대 16,000개(16K)의 세그먼트를 가질 수 있습니다.
## Segmentation Structure (세그멘테이션 구조)

* Divided into two partitions
  세그먼트는 크게 두 가지 파티션으로 나뉩니다.
  1.  **Private (LDT):** 첫 번째 파티션(최대 8K개)은 해당 프로세스 전용이며, **LDT(Local Descriptor Table)**에 저장됩니다.
  2.  **Shared (GDT):** 두 번째 파티션(최대 8K개)은 모든 프로세스가 공유하며, **GDT(Global Descriptor Table)**에 저장됩니다.
## Logical -> Linear -> Physical (논리 -> 선형 -> 물리 주소)
![ch09-main-memory-20251217001750320.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938184/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217001750320.png)
![ch09-main-memory-20251217003949926.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938185/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217003949926.png)
![ch09-main-memory-20251217004047625.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938186/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217004047625.png)
[[그림 상세 설명]]
1.  **CPU generates logical address (Selector + Offset):**
    CPU가 논리 주소를 생성하면, **세그멘테이션 유닛(Segmentation Unit)**에게 '셀렉터(Selector)'를 줍니다.
2.  **Produces linear addresses:**
    세그멘테이션 유닛은 이를 바탕으로 **선형 주소(Linear address)**를 만들어냅니다.
3.  **Linear address given to paging unit:**
    이 선형 주소는 **페이징 유닛(Paging Unit)**으로 전달됩니다.
4.  **Generates physical address:**
    페이징 유닛(MMU 역할)이 최종적으로 메인 메모리의 **물리 주소(Physical address)**를 생성합니다.

* Pages sizes can be 4 KB or 4 MB
  페이지 크기는 4KB 또는 4MB를 지원합니다.

# Intel IA-32 Page Address Extensions (PAE) (페이지 주소 확장)
![ch09-main-memory-20251217003919140.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938185/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217003919140.png)
## Overcoming 4GB Limit (4GB 한계 극복)
* 32-bit address limits led Intel to create page address extension (PAE)
  32비트 주소 체계는 최대 4GB까지만 인식할 수 있다는 한계가 있었습니다. 이를 극복하기 위해 인텔은 **PAE** 기능을 만들었습니다.
* Allowing 32-bit apps access to more than 4GB of memory space
  이를 통해 32비트 시스템에서도 4GB 이상의 물리 메모리에 접근할 수 있게 되었습니다.

## How PAE Works (PAE 작동 방식)
* Paging went to a 3-level scheme
  기존 2단계 페이징을 **3단계 페이징** 구조로 변경했습니다.
* Top two bits refer to a page directory pointer table
  상위 2비트는 '페이지 디렉터리 포인터 테이블'을 가리키는 데 사용됩니다.
* Page-directory and page-table entries moved to 64-bits in size
  페이지 디렉터리와 페이지 테이블의 각 항목 크기를 32비트에서 **64비트**로 늘렸습니다.
* Net effect is increasing address space to 36 bits – 64GB of physical memory
  결과적으로 물리 주소 공간이 36비트로 늘어나, 최대 **64GB**의 물리 메모리를 사용할 수 있게 되었습니다.

# Intel x86-64 (인텔 64비트 아키텍처)
![ch09-main-memory-20251217004724319.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938187/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217004724319.png)
## Massive Address Space (거대한 주소 공간)
* Current generation Intel x86 architecture
  현재 세대의 인텔 아키텍처입니다.
* 64 bits is ginormous (> 16 exabytes)
  이론상 64비트는 16 엑사바이트 이상을 지원하는 엄청난 크기입니다.
* In practice only implement 48 bit addressing
  하지만 실제로는 다 쓰지 않고 **48비트** 주소 체계만 구현하여 사용합니다.

## Paging Hierarchy (페이징 계층)
* Page sizes of 4 KB, 2 MB, 1 GB
  페이지 크기는 4KB, 2MB, 1GB를 지원합니다.
* Four levels of paging hierarchy
  **4단계 페이징** 계층 구조를 사용합니다.
* Can also use PAE so virtual addresses are 48 bits and physical addresses are 52 bits
  PAE를 사용하여 가상 주소는 48비트, 물리 주소는 52비트까지 확장할 수도 있습니다.

# Example: ARM Architecture (ARM 아키텍처 예시)
![ch09-main-memory-20251217004733040.png](https://res.cloudinary.com/dnwyqgjwk/image/upload/v1766938188/obsidian/Knowledge/computer-science/operating-system/ch09-main-memory/assets/ch09-main-memory-20251217004733040.png)
## Mobile Dominance (모바일 지배)
* Dominant mobile platform chip (Apple iOS and Google Android)
  모바일 플랫폼(iOS, Android)을 지배하는 칩입니다.
* Modern, energy efficient, 32-bit CPU
  현대적이고 에너지 효율이 높은 32비트 CPU입니다. (현재는 64비트 ARMv8 등이 주력이지만, 자료는 32비트 기준 설명)
## Page Sizes (페이지 크기)
* 4 KB and 16 KB pages
  일반적인 페이지 크기는 4KB와 16KB입니다.
* 1 MB and 16 MB pages (termed sections)
  1MB와 16MB 크기의 큰 페이지도 지원하며, 이를 **섹션(Sections)**이라고 부릅니다.
## Paging Levels (페이징 단계)
* One-level paging for sections, two-level for smaller pages
  큰 '섹션' 단위는 **1단계 페이징**을 사용하고, 작은 페이지 단위는 **2단계 페이징**을 사용합니다.
## TLB Structure (TLB 구조)
* Two levels of TLBs
  TLB도 두 단계로 나뉘어 있습니다.
  1.  **Outer level (Micro TLBs):** 데이터용 1개, 명령어용 1개로 나뉜 두 개의 작은 마이크로 TLB가 있습니다.
  2.  **Inner level (Main TLB):** 하나의 통합된 메인 TLB가 있습니다.
* First inner is checked, on miss outers are checked
  (일반적인 캐시 구조와 반대로 설명된 듯 보이나 원문 맥락상) Micro TLB를 먼저 확인하고, 없으면 Main TLB를 확인합니다.
* And on miss page table walk performed by CPU
  거기에도 없으면(Miss), CPU가 직접 메모리의 페이지 테이블을 뒤지는 **Page Table Walk**를 수행합니다.
