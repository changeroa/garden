### 1. 하드웨어(MMU)의 검사

CPU가 주소를 요청하면 MMU(메모리 관리 장치)가 페이지 테이블을 봅니다.

- **Valid (v):** "어, 여기 있네?" $\rightarrow$ 즉시 물리 주소로 변환 (통과!)
    
- **Invalid (i):** "어? 유효하지 않네?" $\rightarrow$ **즉시 멈춤! (Trap 발생)**
    

### 2. 운영체제의 판단 (이게 핵심입니다)

하드웨어가 "여기 이상해요!" 하고 인터럽트를 걸면, 운영체제(OS)가 등판해서 **"왜 Invalid인지"** 따져봅니다. 이때 두 가지 경우로 나뉩니다.

#### 경우 A: 진짜 "권한 없는 곳(비워진 곳)"을 건드린 경우

사용자님이 말씀하신 **"비워져 있는 공간"**을 찌른 경우입니다.

- **상황:** 힙과 스택 사이의 구멍(Hole)이나, 아예 할당받지 않은 엉뚱한 주소를 요청함.
    
- **OS의 판단:** "야, 너 여기 쓰겠다고 한 적 없잖아? 남의 땅(혹은 허공)을 왜 건드려?"
    
- **결과:** **Segmentation Fault (세그멘테이션 폴트)** 오류를 띄우고 프로그램을 **강제 종료**시킵니다. (개발자 입장에서 제일 싫은 상황이죠)
    

#### 경우 B: "사용 중"인데 메모리에만 없는 경우 (페이지 부재)

사용자님이 말씀하신 **"이미 사용 중"**인 상황과 비슷합니다. 논리적으로는 내 땅이 맞는데, 물리 메모리(RAM)가 꽉 차서 잠시 하드디스크(스왑 영역)로 쫓겨난 상태일 수 있습니다.

- **상황:** 코드가 실행 중인데 해당 데이터가 잠시 디스크에 가 있음. 페이지 테이블에는 'Invalid'로 표시됨(메모리에 없으니까).
    
- **OS의 판단:** "아, 이거 네 땅 맞지. 근데 지금 창고(디스크)에 가 있네? 내가 가져다줄게."
    
- **결과:** **Page Fault (페이지 폴트)** 처리. OS가 디스크에서 데이터를 읽어와 메모리에 올려주고, 다시 실행시킵니다. (사용자는 멈춘 줄도 모르게 매끄럽게 진행됩니다.)
