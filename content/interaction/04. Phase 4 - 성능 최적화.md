# 04. Phase 4 - 성능 최적화 및 이벤트 폭주 방지

태그: #Phase4 #Performance #Optimization

## 목표: 키 반복/스코프 재평가 오버헤드 최소화 (60fps 유지)

### 문제 상황: "느려요!" - 모든 인터랙티브 시스템의 적

지금까지 설계한 시스템은 정교하지만, 매 이벤트마다 실행된다면 상당한 비용을 치를 수 있습니다.

1.  **스코프 재평가 오버헤드**: `ScopeManager.getActiveScope()`는 DOM을 쿼리하고 CSS 스타일을 계산합니다. 이 작업이 `keydown`이나 `mousemove`처럼 빠르게 반복되는 이벤트마다 실행되면, 브라우저의 렌더링을 방해하여 프레임 드랍(버벅임)을 유발합니다.
2.  **이벤트 폭주(Event Storm)**: 사용자가 키를 꾹 누르고 있으면, 초당 수십 개의 `keydown` 이벤트가 발생합니다. 만약 이 모든 이벤트에 대해 동일한 액션을 반복 실행한다면 이는 CPU 자원의 심각한 낭비입니다.

### 해결 방안 1: 스마트 캐싱 시스템 (Smart Caching System)

**"계산하지 말고, 기억해둔 것을 재사용하라."**

스코프는 UI에 변화가 있을 때만 바뀌지, 사용자가 마우스를 1px 움직인다고 바뀌지 않습니다. 이 점을 이용하여 스코프 계산 결과를 캐싱합니다.

1.  **스코프 캐싱**: `ScopeManager` 내부에 `cachedScope` 변수를 둡니다. `getActiveScope()`가 호출되면, 먼저 캐시된 값이 있는지 확인하고 있다면 즉시 반환합니다.
2.  **캐시 무효화(Cache Invalidation)**: 캐시는 **스코프가 바뀔 가능성이 있는 시점**에만 파기(null로 설정)해야 합니다. 언제일까요?
    -   `click`, `mousedown`: 모달이나 팝오버가 열릴 수 있습니다.
    -   `focusin`, `focusout`: 입력 필드에 포커스가 가거나 빠져나올 때.
    -   `blur`: 창이 비활성화될 때.
    -   `MutationObserver`를 사용하여 DOM의 구조적인 변화(요소 추가/제거)를 감지할 수도 있습니다.
3.  **스로틀링(Throttling)**: 캐시가 무효화되어 스코프를 재계산해야 할 때도, 이 계산 자체를 스로틀링하여 16ms(60fps 목표) 내에 여러 번 실행되지 않도록 보호할 수 있습니다. [[성능 최적화 기법 (Performance Optimization Techniques)]] 참고.

```javascript
class ScopeManager {
  cachedScope = null;

  constructor() {
    // 스코프가 바뀔만한 이벤트가 발생하면 캐시를 날린다.
    const invalidate = () => this.cachedScope = null;
    window.addEventListener('click', invalidate);
    window.addEventListener('focusin', invalidate);
    // ...
  }

  getActiveScope() {
    if (this.cachedScope) {
      return this.cachedScope; // 캐시된 값 반환
    }
    // 캐시가 없으면 실제 계산 수행
    this.cachedScope = this.calculateScope();
    return this.cachedScope;
  }

  calculateScope() { /* ... 실제 DOM 쿼리 로직 ... */ }
}
```

### 해결 방안 2: 이벤트 폭주 방지

**"모든 이벤트를 처리할 필요는 없다."**

1.  **키 반복 감지**: `KeyboardEvent`에는 `repeat`라는 아주 유용한 속성이 있습니다. 키를 꾹 눌러서 발생하는 반복적인 `keydown` 이벤트에서는 이 값이 `true`가 됩니다. 대부분의 단축키는 처음 한 번만 실행되면 충분합니다.

    ```javascript
    function onKeyDown(event) {
      // 키를 꾹 눌러 반복되는 이벤트는 무시
      if (event.repeat) {
        return;
      }
      // ... 단축키 로직 ...
    }
    ```

2.  **엣지 트리거(Edge Triggering)**: `Space` 키를 누르는 동안 패닝(panning) 모드가 되는 기능의 경우, 우리는 상태가 바뀌는 '순간'에만 관심이 있습니다.
    -   `keydown` (non-repeating): 패닝 모드 시작
    -   `keyup`: 패닝 모드 종료
    -   그 사이의 모든 반복적인 `keydown` 이벤트는 무시합니다.

이러한 최적화 기법들을 통해 시스템은 매우 가볍고 반응성이 뛰어나게 유지될 수 있습니다.
