
# 2. Precision Model

GLSL (OpenGL Shading Language)에서는 성능과 정밀도 간의 트레이드오프를 위해 부동소수점(float) 변수의 정밀도를 개발자가 직접 지정할 수 있습니다. 이는 특히 모바일과 같이 성능이 제한적인 환경에서 중요합니다.

`precision mediump float;` // 셰이더 상단에 기본 정밀도를 선언

---

### 정밀도 종류

| 정밀도 | 키워드 | 표현 범위 (대략) | 주요 용도 | 특징 |
| :--- | :--- | :--- | :--- | :--- |
| **High** | `highp` | -2^62 ~ 2^62 | 정점 위치, 깊이 값 | 데스크탑 GPU에서는 `float`이 기본적으로 `highp`. 가장 정확하지만 가장 느림. |
| **Medium** | `mediump` | -2^14 ~ 2^14 | 텍스처 좌표, 색상, 법선 벡터 | 대부분의 시각적 계산에 충분한 정밀도. 성능과 품질의 균형점. 모바일에서 기본. |
| **Low** | `lowp` | -2 ~ 2 | 간단한 색상 값 | 가장 빠르지만 정밀도가 매우 낮아 시각적 오류(Artifacts) 발생 가능. |

-   정수(int)에 대해서도 `highp`, `mediump`, `lowp`를 지정할 수 있습니다.

### 정밀도 오차가 만드는 시각적 문제

#### 경계 진동 (Sparkling Edges)

-   **원인**: `mediump` 또는 `lowp` 정밀도를 사용하여 복잡한 계산(예: 절차적 텍스처, SDF)을 수행할 때, 부동소수점 오차로 인해 경계선 근처의 픽셀 값이 프레임마다 미세하게 달라지는 현상입니다.
-   **증상**: 특정 조건(예: `if (value > 0.5)`)을 만족하는 픽셀의 집합이 매 프레임마다 바뀌면서, 경계선이 마치 반짝이는 것처럼 보입니다. [[🧩 09 - Rendering Lifecycle 디버깅 체계/Rendering Lifecycle 디버깅 체계|미세 떨림(Jitter)]]의 한 형태입니다.

-   **예시**: `mediump`로 계산된 `value`가 실제로는 `0.50001`이어야 하지만 정밀도 한계로 `0.49999`로 계산될 수 있습니다. 이 작은 차이가 `if` 문의 결과를 뒤집어 픽셀이 켜졌다 꺼졌다를 반복하게 만듭니다.

#### 해결 방안

1.  **정밀도 상향**: 문제가 발생하는 변수나 계산에만 `highp`를 명시적으로 사용합니다.
    ```glsl
    highp float complex_calculation = ...;
    ```
2.  **안티에일리어싱 기법 사용**: `if` 문과 같은 날카로운(hard) 경계를 만드는 대신, `smoothstep`이나 [[🟩 05 - Fragment Stage Lifecycle/3. 파생값 계산 (fwidth, dFdx dFdy)|fwidth]]를 사용하여 부드러운(soft) 경계를 만들면 오차가 시각적으로 덜 두드러집니다.
    ```glsl
    // Bad: Hard edge
    // float alpha = (value > 0.5) ? 1.0 : 0.0;

    // Good: Soft edge
    float width = fwidth(value);
    float alpha = smoothstep(0.5 - width, 0.5 + width, value);
    ```
