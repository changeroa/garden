
# 3. 파생값 계산 (fwidth, dFdx/dFdy)

`dFdx`, `dFdy`, `fwidth`는 Fragment Shader에서만 사용할 수 있는 특별한 함수들로, 현재 픽셀과 인접 픽셀 간의 값 변화량(미분값, Derivative)을 계산하여 해상도에 독립적인 렌더링을 가능하게 하는 강력한 도구입니다.

---

### 1. 스크린 공간 기반 미분 (Screen-Space Derivatives)

-   GPU는 보통 2x2 픽셀 그룹 단위로 Fragment Shader를 실행합니다. 이 구조를 이용하여 인접 픽셀 간의 값 차이를 매우 효율적으로 계산할 수 있습니다.

-   **`dFdx(p)`**: 현재 픽셀의 값 `p`와 **오른쪽** 픽셀의 값 `p`의 차이를 계산합니다. (x축 방향의 편미분)
-   **`dFdy(p)`**: 현재 픽셀의 값 `p`와 **아래쪽** 픽셀의 값 `p`의 차이를 계산합니다. (y축 방향의 편미분)

    *`p`는 `float`, `vec2`, `vec3`, `vec4` 타입이 될 수 있습니다.*

### 2. `fwidth(p)`: 픽셀 크기에 자동 적응

-   **`fwidth(p)`** 는 `abs(dFdx(p)) + abs(dFdy(p))` 와 동일합니다.
-   이 값은 **"어떤 값 `p`가 한 픽셀의 크기 동안 얼마나 변하는가"**를 의미합니다.
-   예를 들어, `v_texcoord`라는 텍스처 좌표에 `fwidth`를 적용하면, 텍스처가 화면에 얼마나 확대/축소되었는지에 따라 한 픽셀이 텍스처 공간에서 차지하는 크기를 알 수 있습니다. 이는 밉맵(Mipmap) 레벨을 선택하는 데 사용됩니다.

### 3. AA를 픽셀 크기에 자동 적응시키는 원리

-   `fwidth`의 가장 강력한 용도 중 하나는 [[🧩 09 - Rendering Lifecycle 디버깅 체계/Rendering Lifecycle 디버깅 체계|확대/축소 시 경계 두께가 변하는 문제]]를 해결하는 것입니다.

-   **문제 상황**: `smoothstep(0.4, 0.6, value)` 와 같이 고정된 값으로 안티에일리어싱을 적용하면,
    -   **확대 시**: 경계가 너무 부드러워져 흐릿하게(blurry) 보입니다.
    -   **축소 시**: 경계가 너무 날카로워져 다시 계단 현상(aliasing)이 보입니다.

-   **해결 원리**: 안티에일리어싱이 적용되는 폭(width)을 항상 **1픽셀 크기**에 비례하도록 동적으로 조절합니다.

    ```glsl
    // 'value'는 보통 0을 경계로 하는 SDF 값 같은 것
    float value = ...;

    // 현재 픽셀에서 'value'가 변하는 양, 즉 1픽셀에 해당하는 너비를 계산
    float width = fwidth(value);

    // 0을 중심으로 1픽셀 너비만큼 부드러운 경계를 만듦
    float alpha = smoothstep(-width, width, value);
    ```

-   **결과**: 카메라가 가까워지든 멀어지든, 렌더링 해상도가 바뀌든 상관없이 항상 **시각적으로 일정한 1픽셀 두께의 부드러운 경계선**을 유지할 수 있습니다. 이는 [[🟩 05 - Fragment Stage Lifecycle/4. SDF 기반 렌더링|SDF 기반 렌더링]]의 핵심 기술입니다.
