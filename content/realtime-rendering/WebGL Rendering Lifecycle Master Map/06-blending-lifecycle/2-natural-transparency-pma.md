
# 2. 더 자연스러운 투명도 표현법, PMA

Premultiplied Alpha(PMA)는 반투명 블렌딩 시 발생하는 여러 골치 아픈 문제들을 해결해주는 매우 우아하고 효과적인 방법입니다. 이름 그대로 **'알파 값을 미리 곱해놓은'** 색상 데이터를 사용하는 방식입니다.

-   **일반 알파 (Straight Alpha)**: `(R, G, B, A)` - 우리가 흔히 생각하는 방식
-   **PMA**: `(R×A, G×A, B×A, A)` - RGB 채널에 이미 알파 값이 곱해져 있음

> **비유: 일반 알파가 '물감'과 '투명도'를 따로 사용하는 것이라면, PMA는 처음부터 투명도가 적용된 '반투명 잉크'를 사용하는 것과 같습니다.**

---

### 왜 PMA를 사용할까? (반투명 잉크가 더 좋은 이유)

#### 1. 지저분한 경계선과 색상 왜곡 방지

-   **문제점**: [[06-blending-lifecycle/1. 새로운 색과 기존 색을 섞는 공식|일반적인 알파 블렌딩 공식]]은 색상들이 완벽한 [[07-color-and-gamma-lifecycle/1. 컴퓨터가 계산하는 색 vs 우리 눈이 보는 색|선형(Linear) 공간]]에 있을 때만 수학적으로 올바르게 작동합니다. 하지만 우리가 사용하는 대부분의 이미지(JPG, PNG)는 sRGB라는, 우리 눈에 보기 좋게 살짝 왜곡된 공간에 있습니다.
-   이 왜곡된 sRGB 이미지에 일반 알파 블렌딩을 적용하면, 특히 어두운 색상의 반투명 경계 부분에 **검은색 테두리(dark fringe)가 생기거나 색이 지저분하게 번지는 현상**이 발생합니다.

-   **PMA의 해결책**: PMA는 블렌딩 계산 자체를 더 간단하게 만들어, 이러한 감마 왜곡 문제에 훨씬 더 강한 내성을 갖습니다. 결과적으로 훨씬 깨끗하고 자연스러운 반투명 경계선을 얻을 수 있습니다.

#### 2. 더 정확하고 간단한 블렌딩 공식

PMA를 사용할 때는 블렌딩 레시피도 그에 맞는 것으로 바꿔줘야 합니다.

`gl.blendFunc(gl.ONE, gl.ONE_MINUS_SRC_ALPHA);`

-   **`gl.ONE`**: "새로운 잉크(Source)의 RGB는 이미 알파가 곱해져 있으니, **100% 그대로 사용해라.**"
-   **`gl.ONE_MINUS_SRC_ALPHA`**: "기존 색(Destination)은 평소처럼 **1에서 새로운 잉크의 알파 값을 뺀 만큼** 섞어라."

이 공식은 텍스처를 확대/축소할 때 발생하는 미세한 색상 오류를 줄여주고, 물리적으로 더 정확한 색상 혼합을 보장합니다.

### PMA 작업 흐름 (How-to)

PMA를 올바르게 사용하려면 다음 3가지 규칙을 지켜야 합니다.

1.  **텍스처 로딩 시**: GPU에 이미지를 업로드할 때, "이 이미지는 PMA 방식으로 변환해서 올려줘!" 라고 알려줍니다.
    -   `gl.pixelStorei(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL, true);`

2.  **Fragment Shader 작성 시**: 셰이더에서 색상 계산을 모두 마친 후, 마지막에 RGB 값에 알파 값을 직접 곱해줍니다.
    -   `fragColor.rgb *= fragColor.a;`

3.  **블렌딩 함수 설정 시**: 블렌딩 레시피를 PMA 전용으로 설정합니다.
    -   `gl.blendFunc(gl.ONE, gl.ONE_MINUS_SRC_ALPHA);`

이 세 가지 규칙만 잘 지키면, 포토샵에서 작업한 것과 거의 동일한, 아주 깔끔하고 고품질의 반투명 렌더링 결과를 얻을 수 있습니다.
