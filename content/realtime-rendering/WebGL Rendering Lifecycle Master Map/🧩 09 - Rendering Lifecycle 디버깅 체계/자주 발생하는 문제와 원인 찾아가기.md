
# 자주 발생하는 문제와 원인 찾아가기

열심히 코드를 짰는데 화면에 그림이 이상하게 보일 때, 당황하지 마세요! 대부분의 시각적 문제는 렌더링 파이프라인의 특정 단계에서 발생하는 흔한 실수와 관련이 있습니다. 아래의 진단 차트를 보고 문제의 원인을 함께 찾아봅시다.

> **비유: 환자의 증상을 보고 어느 부분이 아픈지 진단하는 의사의 진단 차트와 같습니다.**

---

| 증상 (Symptom) | 의심되는 단계 (Probable Stage) | 주요 원인 및 해결책 (Common Cause & Solution) |
| :--- | :--- | :--- |
| **화면 전체가 안개 낀 것처럼 흐릿해요.** | [[🟦 02 - Canvas → GPU 진입 단계/1. 그림을 그릴 캔버스 준비하기|1. 캔버스 준비]] | 캔버스 액자 크기(CSS)에만 맞추고, 도화지의 해상도(DrawingBuffer)를 레티나 디스플레이(DPR)에 맞게 높여주지 않았습니다. `canvas.width = css_width * dpr` 공식을 확인해보세요. |
| **경계선이 톱니처럼 울퉁불퉁해요.** | [[🟥 04 - Rasterization Lifecycle/3. 계단 현상을 없애 부드럽게 만들기|3. 안티에일리어싱]] | 계단 현상을 완화하는 안티에일리어싱(AA) 기능이 꺼져있습니다. WebGL 컨텍스트 생성 시 `antialias: true` 옵션을 확인해보세요. |
| **경계선이 파르르 떨리거나 반짝여요.** | [[🟩 05 - Fragment Stage Lifecycle/2. 계산의 정밀도와 품질|2. 셰이더 정밀도]] | 셰이더의 계산 정밀도(`mediump`)가 낮아 소수점 오차가 발생하고 있습니다. `if`문 같은 날카로운 조건 대신 `smoothstep`을 사용하거나, 문제가 되는 변수만 `highp`로 정밀도를 높여보세요. |
| **확대/축소할 때 선 두께가 변해요.** | [[🟩 05 - Fragment Stage Lifecycle/3. 해상도에 구애받지 않는 경계선 만들기|3. fwidth 사용]] | 경계선을 부드럽게 만드는 폭을 고정된 값으로 사용했기 때문입니다. 해상도에 따라 폭을 자동으로 조절해주는 `fwidth` 함수를 사용해서 해결할 수 있습니다. |
| **반투명 경계에 검은 테두리가 생겨요.** | [[🟧 06 - Blending Lifecycle/2. 더 자연스러운 투명도 표현법, PMA|2. PMA 블렌딩]] / [[🟫 07 - Color & Gamma Lifecycle/1. 컴퓨터가 계산하는 색 vs 우리 눈이 보는 색|1. 감마]] | 잘못된 색 공간(sRGB)에서 블렌딩을 하고 있기 때문일 가능성이 높습니다. 더 정확하고 깨끗한 결과를 위해 Premultiplied Alpha(PMA) 워크플로우를 적용해보세요. |
| **반투명 객체가 겹치니 뿌옇게 탁해져요.** | [[🟧 06 - Blending Lifecycle/3. 반투명 객체가 겹칠 때의 문제점|3. 블렌딩 순서]] | 캔버스의 알파 채널 문제입니다. 브라우저가 불투명해야 할 캔버스를 배경과 섞으려고 하고 있습니다. WebGL 컨텍스트 생성 시 `alpha: false` 옵션을 줘보세요. |
| **반투명 객체가 이상하게 보이거나 사라져요.** | [[🟧 06 - Blending Lifecycle/3. 반투명 객체가 겹칠 때의 문제점|3. 블렌딩 순서]] | 반투명 객체를 그리는 순서가 잘못되었습니다. 반드시 **먼 곳의 객체부터 가까운 곳의 객체 순서**로 그려야 합니다. (Z-Sorting) |
| **CSS 색과 WebGL 색이 달라 보여요.** | [[🟫 07 - Color & Gamma Lifecycle/3. CSS 색과 WebGL 색이 같아 보이게 하려면?|3. 색상 일관성]] | WebGL의 색(선형)과 CSS의 색(sRGB)이 다른 색 공간에 있기 때문입니다. [[🟫 07 - Color & Gamma Lifecycle/2. 색상 왜곡을 막는 '감마 보정' 타이밍|올바른 감마 워크플로우]]를 적용하여 색 공간을 통일해야 합니다. |
| **조명/음영이 부자연스럽고 어두워요.** | [[🟫 07 - Color & Gamma Lifecycle/1. 컴퓨터가 계산하는 색 vs 우리 눈이 보는 색|1. 감마]] | 조명 계산을 물리적으로 올바른 선형(Linear) 공간이 아닌, sRGB 공간에서 수행했기 때문입니다. 텍스처를 읽은 후 선형 공간으로 변환하고 계산을 수행해야 합니다. |
| **화면이 가로로 찢어져 보여요.** | [[⚫ 08 - Framebuffer → Display Lifecycle/2. 부드러운 애니메이션의 비밀, VSync|2. VSync]] | VSync(수직 동기화)가 제대로 작동하지 않고 있습니다. `requestAnimationFrame`을 사용하고 있는지 확인해보세요. |
| **애니메이션이 뚝뚝 끊기는 느낌이 들어요.** | [[⚫ 08 - Framebuffer → Display Lifecycle/2. 부드러운 애니메이션의 비밀, VSync|2. VSync]] | 프레임 페이싱이 불안정합니다. 한 프레임을 그리는 데 너무 오래 걸려서(16.67ms 이상) VSync 타이밍을 놓치고 있습니다. 셰이더나 로직을 최적화해야 합니다. |
