
# 5. 투명도(알파)는 어떻게 만들어질까?

Fragment Shader가 최종적으로 결정하는 색상은 RGBA, 즉 빨강(R), 초록(G), 파랑(B), 그리고 **알파(A)**로 이루어져 있습니다. 여기서 알파는 픽셀의 **불투명도(Opacity)**를 의미하며, 0.0(완전 투명)부터 1.0(완전 불투명)까지의 값을 가집니다.

> **비유: 투명한 셀(Cel) 필름 위에 그림을 그리는 것과 같습니다. 알파 값은 물감의 농도를 조절하여, 아래에 놓일 다른 그림이 얼마나 비쳐 보이게 할지를 결정합니다.**

---

### 알파 값은 어디서 오는가?

알파 값은 다양한 방법으로 계산될 수 있습니다.

#### 1. SDF 경계로부터 생성

-   **비유**: 등고선 지도의 해안선에 가까워질수록 물감을 옅게 칠해서, 바다가 자연스럽게 육지와 연결되는 것처럼 보이게 하는 것입니다.
-   **원리**: [[05-fragment-stage-lifecycle/4. 선명한 아이콘과 텍스트의 비밀, SDF|SDF 렌더링]]에서 `smoothstep` 함수의 결과로 나온 0.0 ~ 1.0 사이의 값은 모양의 경계선을 부드럽게 표현합니다. 이 값을 그대로 알파 채널에 사용하면, 모양의 안쪽은 불투명(1.0)하고 바깥쪽은 투명(0.0)하며, 그 경계는 자연스럽게 반투명해집니다.

    ```glsl
    // SDF와 fwidth로 계산된 0.0 ~ 1.0 사이의 알파 값
    float alpha = smoothstep(-width, width, dist);

    // RGB 색상 정보와 알파 값을 결합하여 최종 색상 출력
    fragColor = vec4(shapeColor, alpha);
    ```

#### 2. 텍스처로부터 생성

-   **비유**: 처음부터 투명한 배경을 가진 스티커(PNG 파일)를 필름에 붙이는 것과 같습니다.
-   **원리**: PNG 파일처럼 투명도 정보를 포함하는 텍스처를 사용하는 경우, `texture()` 함수로 읽어온 색상 정보(`texColor`)에 이미 알파 값(`texColor.a`)이 포함되어 있습니다. 이 값을 그대로 최종 출력의 알파 값으로 사용하면 됩니다.

    ```glsl
    // u_texture는 알파 채널이 있는 PNG 이미지
    vec4 texColor = texture(u_texture, v_texcoord);

    // 텍스처의 색상과 알파 값을 그대로 최종 출력으로 사용
    fragColor = texColor;
    ```

### 알파 값의 여정: 다음 단계로 전달

Fragment Shader에서 알파 값을 결정했다고 해서 바로 투명하게 보이는 것은 아닙니다. 알파 값은 다음 단계인 **블렌딩(Blending)**을 위한 **'정보'**일 뿐입니다.

-   **비유**: 셀 필름에 그림을 완성했습니다. 이제 이 필름을 다른 배경 그림 위에 올려놓을 차례입니다. 이때 셀 필름의 투명도(알파)가 아래 배경 그림이 얼마나 비쳐 보일지를 결정합니다.

-   **흐름**:
    1.  Fragment Shader가 최종 색상 `fragColor`를 출력하면, 이 값은 **'소스(Source) 색상'**이 되어 다음 단계로 넘어갑니다.
    2.  이때 `fragColor.a` (알파 값)는 **'소스 알파'**가 됩니다.
    3.  다음 단계인 [[06-blending-lifecycle/1. 새로운 색과 기존 색을 섞는 공식|블렌딩 스테이지]]에서는, 이 '소스 색상'과 '소스 알파'를 가지고, 프레임버퍼에 이미 그려져 있던 **'데스티네이션(Destination) 색상'**과 어떻게 섞을지를 최종적으로 결정합니다.

> **중요**: 만약 블렌딩 기능(`gl.enable(gl.BLEND)`)이 꺼져 있다면, 알파 값은 무시되고 새로 그린 RGB 색상이 기존 그림을 완전히 덮어쓰게 됩니다. 블렌딩이 켜져 있을 때만, 알파 값은 색상을 섞는 비율을 결정하는 중요한 역할을 수행합니다.
