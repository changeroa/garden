
# 3. GPU에 데이터 꾸러미 전달하기

CPU와 GPU는 서로 분리된 공간에서 작동하기 때문에, CPU는 렌더링에 필요한 모든 데이터를 GPU가 알아볼 수 있도록 잘 포장해서 보내줘야 합니다. 마치 멀리 있는 친구에게 **요리 재료가 담긴 택배 상자**를 보내는 것과 같습니다.

---

### 1. VBO: 핵심 재료 상자 (Vertex Buffer Object)

-   **비유**: 요리의 주재료인 **'야채, 고기, 면'**처럼, 3D 모델을 구성하는 핵심 데이터들을 담는 상자입니다.
-   **내용물**: 수많은 정점(Vertex)들의 **위치, 색상, 텍스처 좌표(UV)** 등 대량의 데이터를 담습니다.
-   **특징**: 이 재료들은 보통 게임 시작 시 한 번 보내면, 모델 모양이 바뀌지 않는 한 계속 그대로 사용됩니다. 그래서 `gl.STATIC_DRAW`(정적 데이터)라는 '취급주의' 스티커를 붙여서 보냅니다.
-   **전달 과정**:
    1.  `gl.createBuffer()`: 빈 상자를 만듭니다.
    2.  `gl.bindBuffer(gl.ARRAY_BUFFER, ...)`: "이제부터 이 상자에 재료를 담을 거야!"라고 선언합니다.
    3.  `gl.bufferData(...)`: CPU에 있던 재료들을 상자에 담아 GPU로 보냅니다.

### 2. EBO/IBO: 요리 순서가 적힌 레시피 (Element/Index Buffer Object)

-   **비유**: 재료들을 어떤 순서로 조합해서 요리할지 적어놓은 **'레시피 카드'**입니다.
-   **역할**: 예를 들어 사각형을 그리려면 6개의 점이 필요하지만, 사실 점은 4개만 있으면 됩니다. EBO는 이 4개의 점을 어떤 순서로 연결해서 2개의 삼각형을 만들지 알려줍니다. (예: "1,2,3번 점으로 삼각형 하나, 1,3,4번 점으로 삼각형 둘")
-   **장점**: 중복되는 정점 데이터를 또 보낼 필요가 없어져, 택배 상자의 무게(메모리 사용량)를 줄여줍니다. 배송비가 절약되는 셈이죠!

### 3. VAO: 모든 것을 담은 밀키트 박스 (Vertex Array Object)

-   **비유**: 손질된 재료(VBO), 레시피 카드(EBO), 그리고 각 재료가 어떻게 손질되었는지에 대한 설명서까지, **하나의 요리에 필요한 모든 것을 담은 '밀키트 박스'**입니다.
-   **역할**: VAO는 **상태 기록 장치**입니다. 어떤 VBO를 쓰고, 어떤 EBO를 쓰는지, 그리고 VBO 안의 데이터가 각각 어떤 종류의 정보(위치, 색상 등)인지에 대한 모든 설정을 **한 번에 기억**합니다.
-   **최고의 장점**: 렌더링할 때마다 "위치 정보는 이 상자의 여기서 꺼내고, 색상 정보는 저기서 꺼내고..."라고 복잡하게 설명할 필요가 없습니다. 그냥 **"A 밀키트 박스(`gl.bindVertexArray`)로 요리해!"** 라고 한 번만 말하면, GPU가 모든 세팅을 즉시 알아차립니다. 코드가 매우 간결해지고 실수가 줄어듭니다.

### Attribute vs Uniform: 데이터 종류 비교

| 구분 | 비유 | 설명 | 업데이트 주기 |
| :--- | :--- | :--- | :--- |
| **Attribute** | **개별 재료** (당근, 감자) | 각 정점마다 다른 값 (위치, 색상 등). VBO에 담겨 전달됩니다. | 주로 맨 처음에 한 번 |
| **Uniform** | **공통 양념** (소금, 후추) | 모든 정점에 동일하게 적용되는 값 (모델의 전체 위치, 조명 색상 등). | 매 프레임, 또는 필요할 때마다 |
