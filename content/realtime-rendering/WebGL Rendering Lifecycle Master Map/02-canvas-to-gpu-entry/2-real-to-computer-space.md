
# 2. 현실 공간을 컴퓨터 공간으로 옮기기

3D 렌더링은 결국 3차원의 복잡한 공간을 2차원의 평평한 화면으로 옮기는 과정입니다. 이 과정은 여러 단계의 '좌표 변환'을 통해 이루어지는데, 마치 **디오라마(Diorama)에 놓인 모델 자동차를 카메라로 찍어 사진으로 인화하는 과정**과 매우 유사합니다.

---

### 사진 촬영 과정으로 이해하는 좌표계 변환

#### 1. Local Space (모델 좌표계)
-   **비유**: 아직 상자 안에 있는 '모델 자동차' 그 자체입니다.
-   모델 자동차의 설계도상 중심점이 바로 원점(0, 0, 0)입니다. 바퀴, 문짝 등 모든 부품의 위치는 이 설계도 원점을 기준으로 표현됩니다.

#### 2. World Space (월드 좌표계)
-   **비유**: 모델 자동차를 꺼내 디오라마 세트의 특정 위치에 '배치'하는 단계입니다.
-   디오라마 전체를 아우르는 하나의 공통된 공간입니다. 디오라마의 중심이 원점(0, 0, 0)이 되죠.
-   **모델 행렬(Model Matrix)**: 모델 자동차를 디오라마의 `(x:5, z:10)` 위치에 45도 각도로 돌려놓는 것처럼, 모델을 월드 공간에 배치하는 역할을 합니다.

#### 3. View Space (뷰 / 카메라 좌표계)
-   **비유**: 디오라마를 어떤 각도에서 찍을지 '카메라를 설치'하는 단계입니다.
-   이 공간에서는 카메라 렌즈의 중심이 세상의 원점(0, 0, 0)이 됩니다.
-   **뷰 행렬(View Matrix)**: 실제로는 카메라를 움직이는 게 아니라, 세상 전체를 카메라 앞으로 반대로 움직이고 회전시켜서 원하는 구도를 잡습니다. 예를 들어, 카메라가 위에서 아래를 내려다보는 구도라면, 세상 전체를 카메라 아래로 끌어내리는 셈이죠.

#### 4. Clip Space / NDC (뷰파인더 안의 세상)
-   **비유**: 카메라의 네모난 '뷰파인더'로 세상을 보는 단계입니다.
-   **투영 행렬(Projection Matrix)**이 이 역할을 합니다. 3D 공간을 뷰파인더라는 2D 사각형 안에 '투영'합니다.
    -   **원근 투영**: 멀리 있는 것은 작게, 가까이 있는 것은 크게 보여 현실감을 줍니다.
    -   뷰파인더에 보이는 영역(절두체, Frustum) 바깥의 것들은 과감히 잘라냅니다(Clipping).
-   이 뷰파인더 안의 모든 좌표는最终적으로 가로, 세로, 깊이 모두 **-1에서 +1 사이의 숫자**로 정규화(NDC)됩니다. 이제 해상도와는 상관없는 순수한 비율의 좌표만 남습니다.

#### 5. Screen Space (사진 인화)
-   **비유**: 뷰파인더 속의 이미지를 실제 사진으로 '인화'하는 마지막 단계입니다.
-   -1에서 +1 사이의 NDC 좌표를 [[02-canvas-to-gpu-entry/1. 그림을 그릴 캔버스 준비하기|우리가 준비한 캔버스]]의 실제 픽셀 좌표(예: `x: 520px, y: 230px`)로 최종 변환합니다. 이 과정을 [[03-vertex-stage-lifecycle/3. Viewport Transform|Viewport Transform]]이라고 합니다.

---

### Pixel Snapping: 선명한 사진의 비결

-   **문제**: 인화하려는 이미지의 경계선이 애매하게 픽셀 격자 사이에 걸치면, 색상이 주변 픽셀과 섞이면서 흐릿하게 보일 수 있습니다.
-   **해결**: **픽셀 스냅핑(Pixel Snapping)**은 이 경계선을 가장 가까운 픽셀의 중심에 '착'하고 달라붙게 만들어, [[09-rendering-lifecycle-debugging/Rendering Lifecycle 디버깅 체계|깜빡임이나 흐림 현상 없이]] 선명한 선을 유지시켜주는 기술입니다.
