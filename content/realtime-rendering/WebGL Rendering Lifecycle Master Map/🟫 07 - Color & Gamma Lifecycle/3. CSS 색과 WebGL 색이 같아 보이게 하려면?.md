
# 3. CSS 색과 WebGL 색이 같아 보이게 하려면?

[[🟫 07 - Color & Gamma Lifecycle/2. 색상 왜곡을 막는 '감마 보정' 타이밍|올바른 감마 워크플로우]]를 적용하는 궁극적인 목표 중 하나는, 웹 페이지의 다른 요소(CSS)와 WebGL 캔버스의 색상이 이질감 없이 자연스럽게 어우러지도록 하는 것입니다.

> **비유: 이미 특정 색으로 칠해진 벽(CSS) 옆에, 새로 페인트칠(WebGL)을 할 때 두 색상이 똑같아 보이도록 페인트의 색을 정확히 조색하는 것과 같습니다.**

---

### 1. 왜 CSS 색과 WebGL 색은 달라 보일까?

-   **CSS 색상 (이미 칠해진 벽)**
    -   브라우저는 CSS로 지정된 색상(예: `background-color: #808080`)을 **'사람 눈에 보이는 sRGB 회색'**으로 해석해서 화면에 칠합니다. 즉, 이미 우리 눈에 맞게 감마 보정이 완료된 최종 결과물입니다.

-   **WebGL 색상 (잘못 조색한 페인트)**
    -   만약 WebGL에서 감마 보정 없이 `vec3(0.5, 0.5, 0.5)`를 칠하면, 이것은 **'물리적인 빛의 양이 50%인 선형 회색'**을 의미합니다.
    -   이 '물리적인 색'을 우리 눈에 맞게 변환하는 과정 없이 그대로 모니터에 보내면, 우리 눈에는 훨씬 어둡게 보입니다.

-   **결과**: 똑같은 회색(`_#808080_`과 `_0.5_`)을 목표로 했지만, WebGL로 칠한 부분이 CSS로 칠한 부분보다 **훨씬 어둡게 보이는** [[🧩 09 - Rendering Lifecycle 디버깅 체계/Rendering Lifecycle 디버깅 체계|색상 불일치 문제]]가 발생합니다. 페인트 조색에 실패한 것이죠.

### 2. 감마 불일치가 만드는 시각적 문제들

-   **부자연스러운 대비**: 조명이나 블렌딩 계산을 물리적으로 올바른 선형 공간이 아닌, sRGB 공간에서 잘못 수행하면, 그림의 밝은 부분은 너무 하얗게 날아가고 어두운 부분은 너무 시커멓게 뭉쳐 보입니다.
-   **탁한 색감**: 전체적으로 그림이 마치 안개가 낀 것처럼 탁해(muddy) 보이거나, 대비가 너무 강해 거칠어(harsh) 보일 수 있습니다.

### 3. 시각적 일관성을 달성하는 방법

올바른 페인트 조색법([[🟫 07 - Color & Gamma Lifecycle/2. 색상 왜곡을 막는 '감마 보정' 타이밍|감마 워크플로우]])을 따르면 됩니다.

1.  **전체 공정에 감마 워크플로우 적용**
    -   [[🟫 07 - Color & Gamma Lifecycle/2. 색상 왜곡을 막는 '감마 보정' 타이밍|이전 노트에서 설명한]] '재료 손질(sRGB→Linear) → 요리(Linear) → 플레이팅(Linear→sRGB)' 워크플로우를 파이프라인 전체에 일관되게 적용하는 것이 가장 중요합니다.

2.  **GPU의 자동화 기능 적극 활용**
    -   sRGB 텍스처와 sRGB 프레임버퍼를 사용하여, 이 변환 과정을 최대한 GPU가 자동으로 처리하도록 합니다. 실수를 줄이고 성능도 확보할 수 있습니다.

3.  **셰이더 안의 상수 색상도 변환**
    -   셰이더 코드에 직접 입력하는 색상 값(예: `vec3(1.0, 0.0, 0.0)` )도 CSS 색상처럼 sRGB 값으로 간주해야 합니다. 따라서 이 값들도 다른 텍스처와 마찬가지로, 계산에 사용하기 전에 선형 공간으로 변환(`pow(color, 2.2)`)해주는 것이 원칙입니다.

> **결론: 올바른 감마 워크플로우를 적용하면, WebGL 캔버스는 CSS와 동일한 색상 공간에서 작동하게 되어, 포토샵에서 본 텍스처 색상, CSS로 지정한 UI 색상, 3D 씬의 색상이 모두 조화롭게 어우러지는 시각적 일관성을 달성할 수 있습니다.**
