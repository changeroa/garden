
# 1. 선형 vs sRGB

> **핵심: GPU의 계산은 선형(linear) 공간에서 이뤄지고, 디스플레이는 감마(sRGB)로 본다.**

컴퓨터 그래픽스에서 색상을 다룰 때, 우리는 두 가지 주요 색 공간을 마주하게 됩니다: **선형(Linear) RGB**와 **sRGB**입니다. 이 둘의 차이를 이해하는 것은 정확하고 일관된 색상 렌더링의 핵심입니다.

---

### 1. 선형 공간 (Linear RGB Space)

-   **특징**: 빛의 물리적인 강도에 비례하는 색 공간입니다. 값이 2배가 되면, 빛의 강도(광자 수)도 정확히 2배가 됩니다.
-   **용도**: 모든 물리 기반 렌더링(PBR) 계산, 특히 **조명 계산과 [[🟧 06 - Blending Lifecycle/1. Blend Equation & Factors|블렌딩]]**은 반드시 선형 공간에서 수행되어야 수학적으로 올바른 결과를 얻을 수 있습니다.
-   만약 선형 공간이 아닌 곳에서 조명을 더하면, 색상이 부자연스럽게 어두워지거나 과포화되는 문제가 발생합니다.

### 2. sRGB 공간 (Gamma-Corrected Space)

-   **특징**: 인간의 시각 시스템이 밝기를 인식하는 방식에 맞춰진 비선형(non-linear) 색 공간입니다. 인간의 눈은 어두운 톤의 변화에 더 민감하기 때문에, sRGB는 어두운 영역에 더 많은 비트(데이터)를 할당합니다.
-   **감마(Gamma)**: 선형 공간과 sRGB 공간 사이를 변환하는 곡선 함수를 의미합니다. 일반적으로 약 **2.2**의 감마 값이 사용됩니다.
-   **용도**: 대부분의 이미지 파일(JPG, PNG)과 모니터(디스플레이)는 sRGB 색 공간을 표준으로 사용합니다.

### 3. 변환 관계

-   **Linear to sRGB (감마 보정)**: `sRGB_color = Linear_color ^ (1 / 2.2)`
    -   선형 공간의 색상 값을 어둡게 만들어(어두운 영역의 디테일을 압축하여) sRGB 공간으로 변환합니다.
    -   이 과정은 최종 이미지를 모니터에 표시하기 직전에 수행됩니다.

-   **sRGB to Linear (감마 역보정)**: `Linear_color = sRGB_color ^ 2.2`
    -   sRGB 공간의 색상 값(예: 텍스처)을 밝게 만들어 선형 공간으로 변환합니다.
    -   이 과정은 텍스처를 샘플링한 직후, 조명 계산이나 블렌딩을 수행하기 전에 이루어져야 합니다.

### 왜 선형 공간에서 블렌딩해야 하는가?

-   **예시**: 선형 공간에서 회색(0.5)과 회색(0.5)을 더하면 흰색(1.0)이 됩니다. 이는 물리적으로 올바릅니다.
-   **문제**: sRGB 공간에서 회색(0.5)은 실제로는 선형 공간의 약 0.218 밝기에 해당합니다. `(0.5^2.2)`
    -   만약 sRGB 공간에서 두 회색을 그냥 더하면 `0.5 + 0.5 = 1.0`이 되어 흰색처럼 보이지만, 실제 물리적 밝기는 `0.218 + 0.218 = 0.436`에 불과합니다. 이는 올바른 흰색(1.0)보다 훨씬 어둡습니다.
-   **결론**: [[🟧 06 - Blending Lifecycle/2. Premultiplied Alpha 흐름|알파 블렌딩]] 역시 색상을 더하는 연산이므로, sRGB 공간에서 수행하면 결과가 부자연스럽게 어두워집니다. 따라서 모든 블렌딩은 선형 공간에서 이루어져야 자연스러운 결과를 얻을 수 있습니다.
