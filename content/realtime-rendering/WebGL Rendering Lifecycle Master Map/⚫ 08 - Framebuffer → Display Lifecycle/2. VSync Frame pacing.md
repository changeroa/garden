
# 2. VSync / Frame pacing

GPU가 프레임을 얼마나 빨리 렌더링하는지와 모니터가 화면을 얼마나 자주 새로고침하는지 사이의 관계는 최종적인 시각적 부드러움을 결정하는 중요한 요소입니다. 이 타이밍이 어긋날 때 티어링(Tearing)이나 스터터링(Stuttering) 같은 문제가 발생합니다.

---

### 1. VSync (Vertical Synchronization, 수직 동기화)

-   **역할**: GPU의 프레임 출력 시점을 모니터의 수직 주사(Vertical Blanking Interval) 기간에 맞추도록 강제하는 기술입니다.
-   **목표**: [[⚫ 08 - Framebuffer → Display Lifecycle/2. VSync Frame pacing|티어링(Tearing)]] 현상을 방지하는 것입니다.
-   **브라우저 환경**: `requestAnimationFrame` API는 VSync에 맞춰 콜백을 실행하도록 설계되었습니다. 개발자는 이 콜백 루프 안에서 렌더링을 수행하면 자연스럽게 VSync의 이점을 얻게 됩니다.

### 2. 티어링 (Tearing)

-   **원인**: VSync가 꺼져 있을 때, GPU가 프레임 렌더링을 완료하는 즉시 프레임버퍼를 교체하려고 합니다. 만약 이 교체 시점이 모니터가 화면을 위에서 아래로 그리고 있는 중간에 발생하면, 화면의 윗부분은 이전 프레임의 내용이, 아랫부분은 새로운 프레임의 내용이 표시되면서 이미지가 찢어진 것처럼 보이는 현상입니다.
-   **해결**: VSync를 활성화하여, 모니터가 그림을 다 그리고 쉬는 시간(VBI)에만 프레임버퍼를 교체하도록 합니다.

### 3. 스터터링 (Stuttering)과 프레임 페이싱 (Frame Pacing)

-   **스터터링**: 프레임 속도(FPS)는 높지만, 각 프레임이 화면에 표시되는 간격이 일정하지 않아 시각적으로 뚝뚝 끊겨 보이는 현상입니다. [[🧩 09 - Rendering Lifecycle 디버깅 체계/Rendering Lifecycle 디버깅 체계|미세 떨림(Jitter)]]의 주된 원인입니다.

-   **원인**: 렌더링 시간이 모니터의 주사 간격(예: 60Hz에서 16.67ms)을 초과하거나, 매 프레임마다 렌더링 시간이 크게 변동할 때 발생합니다.
    -   **예시 (프레임 드랍)**: 한 프레임 렌더링에 20ms가 걸렸다고 가정합시다.
        1.  첫 번째 VSync (16.67ms) 시점에는 아직 렌더링이 끝나지 않아 프레임버퍼를 교체하지 못합니다.
        2.  GPU는 렌더링을 계속하고, 20ms 시점에 완료합니다.
        3.  다음 VSync (33.33ms) 시점이 되어서야 비로소 새 프레임이 화면에 표시됩니다.
        4.  결과적으로 한 프레임이 두 번의 주사 기간(33.33ms) 동안 표시된 셈이므로, 순간적으로 FPS가 30으로 떨어진 것처럼 보입니다.

-   **프레임 페이싱 (Frame Pacing)**: 모든 프레임이 일정한 간격으로 화면에 표시되도록 렌더링 시간을 관리하는 기술입니다.
    -   **목표**: 렌더링 시간을 16.67ms 이내로 꾸준히 유지하여, 매 VSync마다 새로운 프레임을 안정적으로 전달하는 것입니다.
    -   이를 위해서는 씬의 복잡도를 조절하거나, 셰이더를 최적화하거나, 동적으로 해상도를 조절하는 등의 기법이 필요합니다.
    -   안정적인 60FPS보다, 30~60FPS를 오가는 불규칙한 프레임 속도가 사용자에게는 훨씬 더 거슬리는 경험을 줍니다.
