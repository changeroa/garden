
# 1. Framebuffer 구조

> **핵심: GPU 내부 계산이 실제 화면 픽셀로 복제되는 마지막 여정.**

Framebuffer Object(FBO)는 WebGL 렌더링의 최종 목적지가 되는 GPU 메모리상의 데이터 묶음입니다. 기본적으로는 화면에 직접 표시될 버퍼를 의미하지만, 오프스크린 렌더링을 위해 사용자가 직접 생성할 수도 있습니다.

---

### Framebuffer의 구성 요소

FBO는 여러 종류의 버퍼(Attachment)를 가질 수 있습니다.

1.  **Color Buffer (색상 버퍼)**
    -   **역할**: 픽셀의 최종 RGBA 색상 값을 저장하는 2D 배열입니다.
    -   **실체**: 보통 텍스처(`gl.TEXTURE_2D`)나 렌더버퍼(`gl.RENDERBUFFER`)가 이 첨부 지점(`gl.COLOR_ATTACHMENT0`)에 연결됩니다.
    -   FBO는 여러 개의 색상 버퍼를 가질 수 있어(Multiple Render Targets, MRT), 한 번의 렌더링 패스로 위치, 노멀, 색상 등 다양한 데이터를 동시에 출력할 수 있습니다.

2.  **Depth Buffer (깊이 버퍼)**
    -   **역할**: 각 픽셀의 깊이(Z) 값을 저장하여 [[🟥 04 - Rasterization Lifecycle/2. Depth & Face Culling|깊이 테스트]]에 사용됩니다.
    -   **실체**: 보통 깊이 정보를 저장하는 특별한 포맷의 텍스처(`gl.DEPTH_COMPONENT24`)나 렌더버퍼가 이 첨부 지점(`gl.DEPTH_ATTACHMENT`)에 연결됩니다.

3.  **Stencil Buffer (스텐실 버퍼)**
    -   **역할**: 각 픽셀에 대한 추가적인 정수 값을 저장합니다. 이를 이용해 특정 영역에만 렌더링을 제한하는 등(예: 그림자, 거울 반사) 복잡한 효과를 구현할 수 있습니다.
    -   **실체**: 보통 깊이 버퍼와 스텐실 버퍼는 하나의 텍스처(`gl.DEPTH24_STENCIL8`)로 묶어서(`gl.DEPTH_STENCIL_ATTACHMENT`) 사용됩니다.

### 기본 Framebuffer vs. 사용자 생성 FBO

-   **기본 Framebuffer (Default Framebuffer)**:
    -   WebGL 컨텍스트가 생성될 때 자동으로 만들어지는 프레임버퍼입니다. ID는 `null`입니다.
    -   이 프레임버퍼에 렌더링하면 결과가 캔버스에 직접 표시됩니다.
    -   `gl.bindFramebuffer(gl.FRAMEBUFFER, null);` 로 바인딩합니다.

-   **사용자 생성 FBO (Off-screen Rendering)**:
    -   `gl.createFramebuffer()`로 생성하고, 텍스처나 렌더버퍼를 각 첨부 지점에 직접 연결(`gl.framebufferTexture2D` 등)해야 합니다.
    -   이 FBO에 렌더링하면 결과가 화면이 아닌, 연결된 텍스처에 그려집니다.
    -   **주요 용도**: 후처리(Post-processing) 효과, 동적 그림자 생성, 반사 맵, G-Buffer 렌더링 등.
    -   오프스크린 렌더링이 끝난 텍스처는 다른 일반 텍스처처럼 다른 객체에 매핑하거나, 화면에 최종적으로 그리는 데 사용됩니다.

### 오프스크린 렌더링 시 스케일/필터링 문제

-   오프스크린 FBO에 연결된 텍스처도 일반 텍스처와 마찬가지로 필터링(Filtering)과 밉맵(Mipmapping) 설정의 영향을 받습니다.
-   **스케일 문제**: 오프스크린 텍스처의 해상도가 최종적으로 그려질 화면 영역의 해상도와 다를 경우, 확대/축소 과정에서 흐림(blur)이나 계단 현상(aliasing)이 발생할 수 있습니다.
-   **필터링 문제**: 특히 `gl.NEAREST` 필터링은 날카로운 픽셀 경계를 만들고, `gl.LINEAR`는 흐릿함을 유발할 수 있습니다. 렌더링 대상의 특성에 맞는 필터링 방식을 선택해야 합니다.
