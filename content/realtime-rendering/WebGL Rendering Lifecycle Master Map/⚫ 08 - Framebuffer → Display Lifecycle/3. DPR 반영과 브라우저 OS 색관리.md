
# 3. DPR 반영과 브라우저/OS 색관리

WebGL의 렌더링 결과물은 독립적으로 존재하는 것이 아니라, 브라우저와 운영체제(OS)의 렌더링 파이프라인의 일부로 최종 화면에 합성됩니다. 이 과정에서 DPR, 브라우저 줌, OS의 색상 관리가 최종 결과물에 영향을 미칩니다.

---

### 1. DPR (Device Pixel Ratio) 반영

-   **재강조**: [[🟦 02 - Canvas → GPU 진입 단계/1. Canvas & Viewport 초기화 흐름|DPR]]은 CSS 픽셀 하나를 렌더링하기 위해 사용되는 물리적 픽셀의 수를 의미합니다. 선명한 결과물을 위해 WebGL의 DrawingBuffer 크기는 반드시 DPR을 고려하여 설정해야 합니다.
    -   `canvas.width = css_width * dpr;`
    -   `canvas.height = css_height * dpr;`
-   **문제**: 이 설정이 잘못되면 [[🧩 09 - Rendering Lifecycle 디버깅 체계/Rendering Lifecycle 디버깅 체계|화면 전체가 흐려지는 문제]]가 발생합니다. 브라우저는 저해상도 DrawingBuffer를 CSS 크기에 맞게 강제로 확대하면서 이미지를 뭉개버립니다.

### 2. 브라우저 줌(Zoom)과 Viewport 일관성

-   **작동 방식**: 브라우저 줌은 기본적으로 페이지의 모든 CSS 크기를 확대/축소하고, DPR 값 자체를 변경하는 것처럼 작동할 수 있습니다.
-   **문제**: 사용자가 페이지를 줌인/줌아웃할 때 `window.devicePixelRatio` 값이 동적으로 변할 수 있습니다. 만약 애플리케이션이 이 변화를 감지하고 캔버스 해상도를 다시 조절하지 않으면, DPR이 맞지 않는 상태가 되어 렌더링이 다시 흐려질 수 있습니다.
-   **해결**: `resize` 이벤트나 `matchMedia` API를 사용하여 DPR의 변화를 감지하고, 캔버스 해상도와 `gl.viewport`를 동적으로 업데이트하는 로직을 구현해야 합니다.
    ```javascript
    const mediaQuery = matchMedia(`(resolution: ${window.devicePixelRatio}dppx)`);
    mediaQuery.addEventListener("change", () => {
      // DPR이 변경되면 캔버스 리사이즈 로직을 다시 실행
      handleResize(); 
    });
    ```

### 3. 운영체제(OS)의 디스플레이 스케일링과 색 관리

-   **OS 스케일링**: Windows의 "배율 및 레이아웃"이나 macOS의 "해상도" 설정은 DPR에 직접적인 영향을 줍니다. 예를 들어, Windows에서 배율을 150%로 설정하면, 브라우저는 DPR을 1.5로 인식합니다.

-   **OS 색 관리 (Color Management)**:
    -   운영체제는 디스플레이의 색상 프로파일(sRGB, Display P3 등)을 인지하고, 애플리케이션이 출력하는 색상을 해당 프로파일에 맞게 변환하여 최대한 정확한 색이 표시되도록 합니다.
    -   **macOS**: 강력한 시스템 레벨 색 관리(ColorSync)를 통해 모든 애플리케이션의 색상을 디스플레이 프로파일에 맞춰 자동으로 변환합니다. 브라우저도 이 정책을 따릅니다.
    -   **Windows**: 전통적으로 색 관리가 애플리케이션별로 이루어졌지만, 최신 버전에서는 OS 레벨의 지원이 강화되고 있습니다.

-   **브라우저의 역할**: 브라우저는 WebGL 캔버스(`HTMLCanvasElement`)를 최종적으로 페이지에 합성할 때, OS의 색 관리 정책을 따릅니다. 만약 WebGL에서 [[🟫 07 - Color & Gamma Lifecycle/2. 감마 보정 타이밍|올바른 감마 워크플로우]]를 통해 sRGB 표준에 맞는 결과물을 출력했다면, 브라우저와 OS는 이 결과물을 디스플레이에 정확하게 재현해 줄 것입니다.
-   결론적으로, 개발자는 WebGL 내부의 색상 공간을 sRGB 표준에 맞게 올바르게 처리하는 데 집중하면, 복잡한 OS 레벨의 색 관리는 대부분 자동으로 처리됩니다.
