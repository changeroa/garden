
# 1. 그림을 그릴 캔버스 준비하기

본격적으로 렌더링을 시작하기 전에, 우리는 먼저 그림을 그릴 도화지를 준비하고 작업 공간을 설정해야 합니다. 이 준비 과정이 잘못되면, 아무리 그림을 잘 그려도 결과가 흐릿하거나 이상하게 보일 수 있습니다.

> **핵심: 선명한 그림을 위해, 캔버스의 물리적인 크기와 해상도를 올바르게 설정한다.**

---

### 1. 캔버스 액자와 실제 도화지

WebGL에서 캔버스는 두 가지 다른 크기의 개념을 가집니다. **'액자 크기'**와 **'도화지 해상도'**입니다.

-   **CSS 크기 (액자 크기)**: `canvas.style.width`
    -   HTML 페이지에서 캔버스가 시각적으로 차지하는 공간의 크기입니다. 마치 그림을 담을 액자의 크기와 같습니다.
    -   액자가 크다고 해서 그림 자체의 품질이 좋아지는 것은 아닙니다.

-   **DrawingBuffer 크기 (도화지 해상도)**: `canvas.width`
    -   실제로 그림이 그려지는 도화지의 픽셀 해상도(가로 픽셀 수 x 세로 픽셀 수)를 의미합니다.
    -   이 해상도가 높을수록 더 촘촘하고 선명한 그림을 그릴 수 있습니다.

### 2. 선명한 그림의 비밀, DPR (Device Pixel Ratio)

-   **DPR이란?**: 레티나 디스플레이처럼 화질이 좋은 고해상도 화면은, 1개의 CSS 픽셀(액자의 점 하나)을 표현하기 위해 여러 개의 물리적인 픽셀(실제 빛나는 점)을 사용합니다. 이 비율을 DPR이라고 합니다. (예: DPR 2.0은 1개의 점을 표현하는 데 2x2=4개의 물리 픽셀을 사용)

-   **왜 중요할까?**: 만약 우리가 DPR을 무시하고 액자 크기에만 맞춰 도화지 해상도를 결정하면, GPU는 듬성듬성한 저해상도 그림을 그린 후, 브라우저가 이 그림을 액자 크기에 맞게 억지로 확대합니다. 그 결과는? [[🧩 09 - Rendering Lifecycle 디버깅 체계/Rendering Lifecycle 디버깅 체계|그림 전체가 흐릿하게(blurry) 보이는 대참사]]가 발생합니다.

-   **해결책**: 도화지 해상도를 DPR만큼 곱해서, 디스플레이의 물리적 픽셀 수와 동일하게 만들어주는 것입니다.
    ```javascript
    // 화면의 픽셀 밀도(DPR)를 가져옵니다.
    const dpr = window.devicePixelRatio || 1;

    // 캔버스 액자의 크기를 가져옵니다.
    const rect = canvas.getBoundingClientRect();

    // 도화지 해상도를 액자 크기 x DPR 로 설정하여 선명하게 만듭니다.
    canvas.width = rect.width * dpr;
    canvas.height = rect.height * dpr;
    ```

### 3. `gl.viewport`: 도화지의 어느 영역에 그릴까?

-   `gl.viewport(x, y, width, height)` 함수는 GPU에게 "준비된 도화지의 특정 영역에 그림을 그려줘"라고 알려주는 역할을 합니다.
-   보통은 도화지 전체를 사용하기 위해 아래와 같이 설정합니다.
    ```javascript
    // 도화지의 왼쪽 아래(0, 0)부터, 도화지 전체 너비와 높이만큼을 사용
    gl.viewport(0, 0, canvas.width, canvas.height);
    ```

### 4. `gl.clear`: 그림 그리기 전 캔버스 청소

-   새 그림을 그리기 전, `gl.clear()` 명령으로 이전 프레임의 잔상을 깨끗이 지웁니다.
    -   `gl.clearColor(r, g, b, a)`: 캔버스를 닦아낼 배경색을 지정합니다.
    -   `gl.clear(gl.COLOR_BUFFER_BIT)`: 지정된 배경색으로 캔버스를 완전히 덮어씌웁니다.
