
# 3. Viewport Transform

> **gl.viewport가 실제 화면 픽셀에 좌표를 매핑하는 방식**

Viewport Transform은 [[🟨 03 - Vertex Stage Lifecycle/2. Clip Space NDC 변환|NDC(Normalized Device Coordinates)]]라는 추상적인 좌표 공간(`-1` ~ `+1`)을 우리가 보는 화면의 실제 픽셀 좌표(Screen Space)로 변환하는 마지막 단계입니다.

이 변환은 `gl.viewport(x, y, width, height)` 명령어로 설정된 사각형 영역을 기준으로 이루어집니다.

---

### Viewport Transform 계산식

`gl.viewport(x, y, w, h)`가 주어졌을 때, NDC 좌표 `(ndc_x, ndc_y)`는 다음과 같이 화면 좌표 `(screen_x, screen_y)`로 변환됩니다.

-   `screen_x = (ndc_x + 1) / 2 * w + x`
-   `screen_y = (ndc_y + 1) / 2 * h + y`

**계산식 완전 정리:**

1.  **`ndc_x + 1`**: `[-1, 1]` 범위를 `[0, 2]` 범위로 이동시킵니다.
2.  **`/ 2`**: `[0, 2]` 범위를 `[0, 1]` 범위로 정규화합니다.
3.  **`* w`**: `[0, 1]` 범위를 `[0, w]` (뷰포트의 너비) 범위로 스케일링합니다.
4.  **`+ x`**: 뷰포트의 시작점 `x`만큼 평행 이동하여 최종 픽셀 x좌표를 얻습니다.

(y좌표도 동일한 원리로 계산됩니다.)

### DPR과 픽셀 단위 경계 계산

-   [[🟦 02 - Canvas → GPU 진입 단계/1. Canvas & Viewport 초기화 흐름|DPR(Device Pixel Ratio)]]이 1보다 큰 디스플레이에서는 CSS 픽셀과 물리적 픽셀의 수가 다릅니다. WebGL의 `gl.viewport`는 **물리적 픽셀**을 기준으로 작동합니다.

-   예를 들어, 300x150 CSS 픽셀 크기의 캔버스가 DPR 2.0 디스플레이에 있다면:
    -   캔버스의 DrawingBuffer 크기는 `600x300` 픽셀이 되어야 선명합니다.
    -   `gl.viewport`는 `gl.viewport(0, 0, 600, 300)`으로 설정해야 합니다.

-   **경계 계산의 중요성**:
    -   만약 `gl.viewport(0, 0, 300, 150)`으로 잘못 설정하면, NDC 공간 전체가 캔버스 좌측 하단의 1/4 영역에만 렌더링되고, 나머지 영역은 비어있게 됩니다.
    -   반대로, DPR 1.0 환경에서 `gl.viewport(0, 0, 600, 300)`으로 설정하면, 렌더링 결과의 좌측 하단 1/4만 캔버스에 보이게 됩니다.

-   따라서, `gl.viewport`의 `width`, `height` 파라미터는 항상 `canvas.width`, `canvas.height` (DrawingBuffer의 실제 픽셀 크기)와 일치시켜야 의도한 대로 렌더링됩니다.
