
# 3. 레티나 디스플레이와 브라우저 줌의 영향

우리가 WebGL로 그린 그림은 독립적으로 존재하는 것이 아니라, 브라우저와 운영체제(OS)라는 더 큰 시스템 안에서 최종적으로 사용자에게 보여집니다. 따라서 이 외부 환경들이 그림의 최종 모습에 어떤 영향을 미치는지 이해해야 합니다.

> **비유: 우리가 그린 그림이 미술관(브라우저/OS)에 전시되는 것과 같습니다. 미술관의 조명이나 관람객이 사용하는 돋보기(줌)에 따라 그림이 다르게 보일 수 있습니다.**

---

### 1. DPR: 최고급 캔버스의 품격

-   **비유**: 레티나(Retina) 같은 고해상도 디스플레이는 일반 캔버스보다 훨씬 더 촘촘한 올을 가진 **최고급 캔버스**입니다. 이 촘촘한 정도가 바로 [[02-canvas-to-gpu-entry/1. 그림을 그릴 캔버스 준비하기|DPR(Device Pixel Ratio)]]입니다.

-   **재차 강조**: 이 최고급 캔버스의 촘촘한 올(물리적 픽셀)의 수에 맞춰 그림의 해상도를 높여주지 않으면(`canvas.width = css_width * dpr`), 브라우저는 저화질로 그려진 그림을 억지로 늘려서 전시하게 됩니다. 그 결과는 [[09-rendering-lifecycle-debugging/Rendering Lifecycle 디버깅 체계|그림 전체가 흐릿하게 보이는 대참사]]입니다. 선명한 렌더링을 위한 제1원칙은 DPR을 올바르게 반영하는 것입니다.

### 2. 브라우저 줌: 관람객의 돋보기

-   **비유**: 관람객이 돋보기(브라우저 줌 기능)를 꺼내서 그림을 확대하거나 축소해서 보는 것과 같습니다.

-   **문제점**: 사용자가 페이지를 줌인/줌아웃(`Ctrl` + `+`/`-`)하면, 돋보기의 배율이 바뀌는 것처럼 `window.devicePixelRatio` 값이 동적으로 변할 수 있습니다. 만약 우리 코드가 이 변화를 감지하고 그림의 해상도를 다시 조절해주지 않으면, 그림의 해상도와 돋보기 배율이 맞지 않아 또다시 그림이 흐릿해지는 현상이 발생합니다.

-   **해결책**: 똑똑한 전시 프로그램은 관람객이 돋보기를 바꿀 때마다(`resize` 이벤트나 `matchMedia` API 사용) 그림의 해상도를 그에 맞게 실시간으로 다시 조절하여, 어떤 줌 레벨에서도 최상의 선명도를 유지해야 합니다.

### 3. OS 색 관리: 미술관의 조명 시스템

-   **비유**: 미술관의 정교한 조명 시스템(OS 색 관리)이 그림의 색을 최종적으로 관람객에게 어떻게 보여줄지 결정하는 것과 같습니다.

-   **원리**: 운영체제(macOS, Windows)는 현재 사용 중인 모니터의 색상 표현 특성(색상 프로파일)을 알고 있습니다. 그리고 각 프로그램이 출력하는 색상(예: sRGB)을 모니터의 특성에 맞게 실시간으로 변환하여, 어떤 모니터에서 보더라도 최대한 원작자의 의도와 가까운 색이 표시되도록 합니다.

-   **우리가 할 일**: 다행히도, 이 복잡한 조명 시스템은 우리가 직접 제어할 필요가 거의 없습니다. 우리가 할 일은 단 하나, **국제 표준(sRGB)에 맞춰서만 결과물을 만들어내는 것**입니다.

> **결론: 우리는 [[07-color-and-gamma-lifecycle/2. 색상 왜곡을 막는 '감마 보정' 타이밍|올바른 감마 워크플로우]]를 통해 sRGB라는 표준에 맞는 결과물만 잘 만들어주면, 브라우저와 OS가 알아서 '미술관 조명'을 조절하여 사용자에게 가장 정확한 색을 보여줍니다. 복잡한 색 관리는 시스템에 맡기고, 우리는 표준을 지키는 데만 집중하면 됩니다.**
