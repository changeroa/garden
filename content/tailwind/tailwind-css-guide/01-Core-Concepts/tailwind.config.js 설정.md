## 📝 핵심 정리
`tailwind.config.js` 파일은 프로젝트의 디자인 시스템을 코드로 정의하는 곳입니다. 색상, 폰트, 간격, 브레이크포인트 등 모든 시각적 요소를 중앙에서 관리하고 커스터마이징할 수 있습니다.

## 💻 코드 예제 (config 파일 커스터마이징)

/**
 * ==========================================
 * [기능명]: `tailwind.config.js` 확장 및 재정의
 * ==========================================
 *
 * 📖 목적: 기본 테마를 확장하여 프로젝트만의 고유한 디자인 시스템을 구축합니다.
 * 🏗️ 구조: `theme.extend` 객체 안에 새로운 값을 추가하여 기존 설정을 유지하면서 새로운 옵션을 더합니다.
 * 🔄 흐름: Tailwind 빌드 프로세스가 시작될 때 이 파일을 읽어, 기본 설정과 사용자 정의 설정을 병합하여 최종 디자인 토큰을 생성합니다.
 * 🎯 학습포인트: `extend`를 사용하면 기본값을 유지한 채 추가할 수 있고, `theme` 바로 아래에 정의하면 기본값을 덮어쓴다는 차이점을 이해합니다.
 */

```javascript
// tailwind.config.js

module.exports = {
  content: [
    './src/**/*.{js,jsx,ts,tsx}', // JIT가 스캔할 파일 경로
  ],
  theme: {
    extend: { // 기본 테마 확장
      colors: {
        'brand-primary': '#1a73e8',
        'brand-secondary': '#fbbc05',
      },
      spacing: {
        '128': '32rem',
      },
      fontFamily: {
        sans: ['Inter', 'sans-serif'],
      },
    },
  },
  plugins: [ // 플러그인 추가
    require('@tailwindcss/forms'),
  ],
}
```

## 🔍 상세 분석

### 설정 항목
- **`content`**: JIT 컴파일러가 클래스를 스캔할 파일의 경로를 지정합니다. 여기에 포함되지 않은 파일의 클래스는 생성되지 않습니다.
- **`theme`**: 디자인 시스템의 핵심. `colors`, `spacing`, `fontSize`, `screens` 등 모든 디자인 토큰이 정의됩니다.
- **`theme.extend`**: 기본 설정을 유지하면서 새로운 값을 추가하는 가장 일반적인 방법입니다.
- **`plugins`**: `tailwindcss/forms`, `tailwindcss/typography` 등 공식/커뮤니티 플러그인을 추가하여 새로운 유틸리티를 확장합니다.

### 실무 포인트
- **중앙 관리**: 모든 디자인 관련 결정이 이 파일 하나로 모이므로, 프로젝트 전체의 일관성을 유지하기 쉽습니다.
- **문서화**: `tailwind.config.js` 파일 자체가 팀의 디자인 시스템을 설명하는 살아있는 문서 역할을 합니다.
- **재사용성**: 잘 정의된 설정 파일은 다른 프로젝트에서도 재사용할 수 있습니다.
