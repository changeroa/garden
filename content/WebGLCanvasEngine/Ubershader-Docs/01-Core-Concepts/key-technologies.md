## 📖 개념 설명
Ubershader의 성능과 품질은 세 가지 핵심 WebGL 기술 덕분입니다.

### 1. 인스턴스 렌더링 (Instanced Rendering)
- **무엇인가?**: 동일한 형태의 객체(여기서는 사각형)를 수천, 수만 개 그릴 때, 단 한 번의 렌더링 명령으로 모두 처리하는 기술입니다.
- **어떻게 동작하는가?**
  1. **기본 도형 정의**: 사각형을 구성하는 6개의 정점(`a_position`) 데이터를 한 번만 GPU에 보냅니다.
  2. **인스턴스 데이터 전송**: 각 사각형(인스턴스)의 고유한 정보(위치, 크기, 색상 등)를 배열 형태로 GPU에 보냅니다. `Ubershader.ts`의 버텍스 셰이더는 다음 `in` 속성들을 통해 이 데이터를 받습니다.
     - `in vec2 a_instancePos`: 노드 중심 위치
     - `in vec2 a_instanceSize`: 노드 크기
     - `in vec4 a_instanceColor`: 노드 색상
     - `in float a_selected`: 선택 상태
  3. **GPU에서 조합**: 버텍스 셰이더는 각 인스턴스를 그릴 때마다 기본 도형 데이터와 해당 인스턴스의 고유 데이터를 조합하여 최종 위치와 모습을 계산합니다.
- **장점**: CPU가 GPU에 `gl.drawArraysInstanced()` 같은 명령을 단 한 번만 호출하도록 만들어, 객체 수에 상관없이 일정한 성능을 유지합니다.

### 2. SDF (Signed Distance Fields)
- **무엇인가?**: 각 픽셀 위치에서 가장 가까운 도형 경계까지의 '부호 있는 거리'를 나타내는 필드(데이터)입니다. 셰이더 내에서 수학적으로 실시간 계산됩니다.
- **어떻게 동작하는가?**
  - **거리 값의 의미**:
    - `거리 < 0`: 픽셀이 도형 내부에 있음
    - `거리 = 0`: 픽셀이 정확히 도형 경계에 있음
    - `거리 > 0`: 픽셀이 도형 외부에 있음
  - **렌더링**: 프래그먼트 셰이더는 각 픽셀의 SDF 값을 계산하여, 이 값이 0에 가까울수록 경계로 판단하고 부드럽게 색상을 채워(안티앨리어싱) 렌더링합니다.
  - **코드 연결**: `Ubershader.ts`의 프래그먼트 셰이더는 다음 코드를 통해 SDF를 계산합니다.
    ```glsl
    // abs(pos - center)는 중심에서의 거리, size는 모서리 반지름이 적용된 사각형 크기
    vec2 d = abs(pos - center) - size; 
    // 둥근 모서리를 포함한 최종 거리 계산
    float distance = length(max(d, 0.0)) + min(max(d.x, d.y), 0.0) - u_cornerRadius;
    ```
- **장점**:
  - **해상도 독립성**: 이미지가 아닌 수학 공식이므로 확대해도 깨지지 않습니다.
  - **유연한 스타일링**: `ShaderUniforms` 인터페이스의 `u_cornerRadius` (모서리 둥글기), `u_borderWidth` (테두리 두께) 같은 값을 TypeScript 코드에서 변경하는 것만으로 테두리, 그림자, 둥근 모서리 등의 효과를 쉽게 제어할 수 있습니다.

### 3. 타입스크립트 통합 (TypeScript Integration)
- **강력한 타입 시스템**: `UberShader` 클래스와 관련 인터페이스(`ShaderCompileResult`, `ShaderUniforms`)는 타입스크립트로 작성되어 개발 단계에서부터 오류를 방지합니다.
- **명확한 API**: `compile()`, `setUniforms()`, `use()` 등의 메서드는 목적이 명확하며, `Partial<ShaderUniforms>`와 같은 타입을 사용하여 필요한 유니폼만 선택적으로 업데이트할 수 있는 유연성을 제공합니다.
- **자동 완성 및 문서화**: 타입 정의는 코드 편집기에서 자동 완성, 매개변수 정보, 문서 확인을 용이하게 하여 생산성을 높입니다.
